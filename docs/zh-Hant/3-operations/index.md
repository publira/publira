這些頁面是寫給已經在提供服務的安裝實例的營運人員，也就是[部署](../2-deployments/index.md)完成後的狀態。內容涵蓋第一個租戶之後的工作：新增更多租戶、管理誰可以登入各個主控台、維護平台本身的帳戶，以及變更`publiractl setup`所設定的服務。

這些工作大多可以從`publiractl`命令列或平台主控台進行。第一頁說明如何選擇，之後的每一頁在兩種方式都可行時，會同時說明兩種方式。

## 本節內容

- [平台主控台與publiractl](./1-platform-console.md)：如何在兩者之間選擇、建立第一位營運人員，以及登入平台主控台的營運人員。
- [租戶](./2-tenants.md)：建立租戶、它的網域與主控台主機、變更它們，以及暫停租戶。
- [租戶的工作人員](./3-tenant-staff.md)：登入租戶主控台的人員、他們的角色、邀請，以及讓失去最後一位管理員的租戶恢復運作。
- [使用者](./4-users.md)：每個租戶的讀者，以及營運人員可以對他們的帳戶做什麼。
- [物件儲存](./5-object-storage.md)：保存每張圖片的儲存貯體、它的認證資訊，以及圖片如何在`/images`下轉換、快取與傳送。
- [電子郵件](./6-email.md)：平台的SMTP帳戶與租戶自己的SMTP帳戶、安裝實例寄送的郵件、HTML郵件，以及郵件中的連結會連到哪裡。
- [搜尋](./7-search.md)：網站的搜尋引擎、從資料庫移到OpenSearch或Elasticsearch、文字分析，以及重建索引。
- [Web Push](./8-web-push.md)：開啟瀏覽器通知，以及簽署通知所用的金鑰組。
- [平台預設值與政策](./9-platform-policies.md)：每個租戶繼承的預設值、安全性與社群限制，以及保留期限，還有租戶可以變更其中哪些。
- [排程工作與維護工作](./10-scheduled-jobs.md)：`publira worker`自行執行的工作、它如何在停機後補做並重試寄出的郵件、推播與快取重新驗證，以及如何以`publiractl job`手動執行工作。
- [監控](./11-monitoring.md)：每個處理程序回應的健康檢查及其探測方式、值得設定警示的日誌行與指標，以及開啟OpenTelemetry指標與追蹤。
- [保護安裝實例](./12-security/index.md)：讓租戶與認證資訊彼此隔離的機制，以及每個密鑰可以放在哪裡。
  - [輪替密鑰](./12-security/1-rotating-secrets.md)：替換加密金鑰、資料庫密碼、簽署金鑰與權杖。
  - [兩步驟驗證](./12-security/2-two-step-verification.md)：要求租戶工作人員與平台營運人員使用兩步驟驗證。
  - [稽核記錄](./12-security/3-audit-logs.md)：平台主控台的記錄與租戶的記錄會記錄什麼，以及兩者都不記錄什麼。
  - [Web應用程式防火牆](./12-security/4-waf.md)：要開啟的受管理規則，以及Publira的上傳與webhook所需的例外。
  - [速率限制](./12-security/5-rate-limits.md)：在安裝實例前方應依用戶端限制哪些請求，以及如何把限制寫成WAF規則或寫在您執行的代理中。

若您還沒讀過Publira是什麼，請從[快速入門](../1-getting-started.md)開始。

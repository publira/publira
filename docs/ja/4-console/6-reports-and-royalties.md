管理画面のいくつかの画面は、サイトで起きたことを数値にします。**ダッシュボード**は、作品の公開がどこまで進んでいるかを示します。**アナリティクス**の下では、**売上**が売れたものを、**読者の反応**が読者が各シリーズをどれだけフォローし、読み、リアクションしたかを、**エピソード**が会員が各エピソードをどこまで読んだかと読者が離れるページを、**コホート**が毎週登録した読者がその後も訪れ続けたか、そのうち何人が購入したかを示します。**レポート**の下の**印税**は、1か月分の売上についてテナントが各著者に支払うべき金額を計算し、その月を締めて、以後変わらない明細にします。

**ダッシュボード**、**読者の反応**、**エピソード**、**コホート**は、スタッフのすべてのメンバーに表示されます。**売上**、**印税**、**コホート**の**ファネル**が表示され、レポートや明細をCSVでダウンロードし、月を締め、月の締め方を変更できるのは**テナント管理者**だけです。それ以外の人には、これらの画面と操作は表示されません。

## 販売や閲覧がどの日に数えられるか

これらの画面が集計に使う日付は、どれも**設定** › **基本情報** › **タイムゾーン**で設定したテナントのタイムゾーンでの暦日です。一度も設定していないテナントは、オペレーターが選んだインストール環境の既定のタイムゾーンを使います。1日はそのタイムゾーンでの午前0時から午前0時まで、1か月はその月の初日の00:00から翌月の初日の00:00までです。東京で4月1日の08:30に行われた販売は、`Asia/Tokyo`のテナントでは4月に、`UTC`のテナントでは3月に数えられます。そのタイムゾーンではまだ3月31日の23:30だからです。

- 販売は購入が記録された時点に数えます。コンビニ決済のように後から支払われる方法では、支払いが届いた時点です。
- 閲覧は、会員がエピソードを開いた日、または読み終えた日に数えます。
- フォローはフォローした時点に数え、その終わりは、読者がフォローを外した時点またはアカウントを削除した時点です。
- 明細は、その月を区切ったときのタイムゾーンを保持し、月の下に「**締めた時点のテナントのタイムゾーン（タイムゾーン名）で区切っています。**」と表示します。

明細を締めた後にタイムゾーンを変更しても、その明細は締めたときのままです。その翌月は、明細が終わった時点、つまり古いタイムゾーンの午前0時に始まり、新しいタイムゾーンの午前0時に終わります。そのため、2つの午前0時のあいだの時間帯に行われた販売は、古いタイムゾーンで属していた月に1回だけ数えられます。それ以降の月は、新しいタイムゾーンの午前0時から午前0時までです。**読者の反応**と**エピソード**が読み取る日次統計ですでに集計された日は集計し直されず、変更は次に集計される日から適用されます。**売上**と**読者の反応**のフォロワーは、販売とフォローそのものから読み取るため、すぐに新しいタイムゾーンに従います。

## ダッシュボード

管理画面の最初の項目である**ダッシュボード**は、販売や閲覧ではなく、作品の公開状況の概要です。3つの数値は期間を区切らず、テナント全体を数えます。

| 数値                 | 数えるもの                         |
| -------------------- | ---------------------------------- |
| **公開中シリーズ**   | 公開されているシリーズ             |
| **下書きエピソード** | 下書きとして保存されたエピソード   |
| **予約公開**         | 公開日時がまだ来ていないエピソード |

**公開キュー**には、それらのエピソードが最大10件表示されます。まず予約済みのものが公開日時の近い順に、次に下書きが新しい順に並びます。**予定**はテナントのタイムゾーンで表示され、日時のない下書きでは**未設定**と表示されます。その横の**カレンダーを開く**を選ぶと[カレンダー](./1-catalog/2-episodes.md#何がいつ公開されるか)が開き、予約済みと公開済みのすべてのエピソードが公開される日ごとに表示されます。

![ダッシュボード。公開中のシリーズ1件、下書きのエピソード1件、予約公開1件と、タイトルの横にカレンダーを開くがある公開キュー。キューには予約済みのエピソードが日時とともに先頭に、その後に未設定の下書きが表示されている。](./reports-and-royalties-dashboard.png)

スタッフのメンバーがシリーズやエピソードを保存するとすぐに、また予約済みのエピソードが自動で公開されたときにも、画面は更新されます。公開されたエピソードはキューから外れます。

## アナリティクス

**売上**、**読者の反応**、**コホート**、エピソードの離脱は、それぞれテナントの日付での期間について集計します。期間は**開始日**と**終了日**で選んで**適用**を押し、最長366日です。選ばない場合、画面は昨日までの（昨日を含む）28日間を対象にし、日付の下の行に期間とタイムゾーンが表示されます。**リセット**を押すと、その28日間に戻ります。

画面の最初には期間の合計と日ごとのグラフがあり、その下に表があります。**日別**、**シリーズ別**、**エピソード別**で表の行を選び、列の見出しを選ぶとその列で表を並べ替え、もう一度選ぶと逆順に並べ替えます。期間、行、並び順はすべてページのアドレスに含まれるため、ブックマークやリンクから同じレポートを開き直せます。

日次統計に基づく数値は、その日が終わってから反映されます。`publira worker`は、テナントのタイムゾーンで午前0時を過ぎた後の、次の1時間ごとの処理で各日を集計します。そのため、今日の閲覧は明日表示されます。ワーカーが止まっているあいだは新しい日は集計されず、再び動き出すと、集計できなかった日を取り戻します。`publira worker`を稼働させ続ける方法は[概要](../2-deployments/1-overview.md)で説明します。

### 売上

**売上**は、期間内に売れたものをテナントの通貨で示します。

| 数値 | 数えるもの |
| --- | --- |
| **購入数** | 期間内に行われた購入で、返金されたものも含みます |
| **総売上** | それらの購入で支払われた金額 |
| **返金額** | それらの購入について読者に戻った金額です。返金と、テナントが認められなかった異議申し立てです |
| **純売上** | **総売上**から**返金額**を引いた、テナントに残った金額 |

グラフは各日の純売上です。販売は行われた日に数え、その販売について戻った分は、どれだけ後に戻ったとしても同じ日から差し引きます。そのため、すでに報告した日の数値が後から下がることがあり、売れた額より戻った額が多い日は線の下に描かれます。まだ結論の出ていない異議申し立ては、認められなかったと決まるまで何も差し引きません。巻やシリーズの残りのエピソードの購入は、それで読めるようになった各エピソードの販売として、価格のうちそのエピソードが占める部分（印税明細で計上されるのと同じ部分）で数え、シリーズの販売としては価格全体で数えます。テナントの現在の通貨とは別の通貨で支払われた購入は、どの数値にも含まれません。テナントのコインで支払われたエピソードは、そのコインに支払われた金額（印税明細で計上されるのと同じ金額）の販売として数えます。コインのパックの購入はどの数値にも含まれません。その代金はコインが使われるにつれて数えられ、パックの全額返金やパックへの異議申し立ては、使われたコインによる販売から差し引かれます。売上は購入そのものを読み取るため、たった今行われた販売もすでに含まれています。

### 読者の反応

**読者の反応**は、期間内に読者がテナントのシリーズをどれだけフォローし、読み、リアクションしたかを示します。

| 数値 | 数えるもの |
| --- | --- |
| **フォロワー** | 期間の終わりにフォローしている読者です。フォローはした時点ですぐに数え、読者がフォローを外したときやアカウントを削除したときに終わります |
| **閲覧数** | シリーズのページとそのエピソードの閲覧で、ログインしているかどうかにかかわらず、すべての読者の閲覧です |
| **完読数** | 会員がそのシリーズのエピソードを初めて読み終えた数 |
| **リアクション** | エピソードのリアクションの操作が押され、読者のそのエピソードへのスコアが増えた回数 |

グラフは各日の終わりのフォロワーです。**シリーズ別**にはすべてのシリーズが、期間内に行われたフォローと終わったフォロー、そして**評価**と**評価した読者**とともに表示されます。評価は期間のものではなく、シリーズのページに表示されるのと同じ、これまでに集まったすべてのリアクションに基づく現在の評価です。どの読者も評価していないシリーズには`—`と表示されます。

### エピソード

**エピソード**は、開いた各エピソードを読み終えた会員の数を示します。ほかの画面がどの期間を表示していても、数値はテナントのタイムゾーンで昨日までの（昨日を含む）直近28日間が対象で、タイトルの下の行に日付とタイムゾーンが表示されます。

| 数値 | 数えるもの |
| --- | --- |
| **完読数** | 会員がエピソードを読み終えた数です。何度読み直しても、会員はエピソードごとに1回、初めて読み終えた日に数えます |
| **会員閲覧数** | ログインしている会員がエピソードを開いた回数です。1人の会員が1つのエピソードを開いた回数は、時計の30分ごと（:00から:29までと:30から:59まで）に1回と数えます。そのため、同じ30分のうちに開き直しても増えませんが、10:29に開いて10:30にもう一度開くと2回と数えます |
| **読了率** | **完読数**を**会員閲覧数**で割った値で、閲覧がない場合は`—`と表示されます |

数えるのはログインしている会員だけです。ログインしていない読者は読み終えたことを記録できないため、その閲覧も除きます。会員がどのようにしてエピソードを読んだかは関係ありません。購入したエピソードも、チケットで開いたエピソードも、無料のエピソードも同じように数え、購入しただけでは何も数えません。

**読了率**の一覧には、期間内に読まれた各エピソードが完読数の多い順に、1ページに20件ずつ表示されます。上部の合計は、どのページを表示していても期間全体の値です。

![日付を示す行の下のエピソード画面。完読数、会員閲覧数、読了率、読了率の計算方法、読了率の一覧。](./reports-and-royalties-read-through.png)

#### 離脱

**読了率**の一覧でエピソードを選ぶと、その**離脱**が開きます。期間内に読者がエピソードのどこまで読み進めたかを、ページごとに示します。

| 数値                     | 数えるもの                             |
| ------------------------ | -------------------------------------- |
| **読者**                 | 最初のページに到達した読者             |
| **最後のページまで到達** | エピソードの最後のページに到達した読者 |
| **ページ数**             | エピソードの現在のページ数             |

グラフは最初のページから最後のページへと段階的に下がり、表には各ページについて、そのページに到達した読者、最初のページに到達した読者に占めるその割合、そのページで離れた読者（そのページには到達したが次のページには到達しなかった読者）が表示されます。**ここで離脱**で並べ替えると、もっとも多くの読者が離れたページが先頭に来ます。読者は、1日の終わりの時点でエピソード内の読書位置があったページに数えます。そのため、期間内の複数の日に読んだ読者は、それぞれの日に1回ずつ数えます。エピソードの最後のページより後にあり、「**（削除済み）**」と表示されるページは、エピソードからページが削除される前に到達されたものです。

### コホートとファネル

**コホート**は、期間内の各週に登録した読者を追跡します。ここでの読者はテナントのサイトのアカウントで、スタッフ自身のアカウントは除きます。

**登録週ごとの継続率**には、期間に1日でも含まれる週ごとに行があります。週はテナントのタイムゾーンでの月曜日から日曜日までなので、最初の行は**開始日**より前に始まり、最後の行は**終了日**より後に終わることがあります。各行には、週、その週にアカウントが作成された読者の数、そして**0週目**から**12週目**の下に、登録した週とその後の12週のそれぞれについて、いずれかの日にエピソードを閲覧した、読み終えた、または購入した読者の割合が表示されます。読者は、何日訪れても1週につき1回と数えます。セルの色が濃いほど割合が大きいことを示します。週が表に反映されるのは、その週が終わり、その週の日が集計されてからです。そのため、進行中の週は空欄になり、誰も登録しなかった週の行には`—`と表示されます。

**シリーズ**でシリーズを選ぶと、そのシリーズの閲覧と購入だけを数えます。行は引き続き登録したすべての読者なので、割合は、その週の新しい読者のうちどれだけがそのシリーズに進んだかを示します。

**テナント管理者**に表示される**ファネル**は、期間内に登録した読者と、その読者がどこまで進んだかを数えます。

| 段階 | 数えるもの |
| --- | --- |
| **登録した** | 期間内にアカウントが作成され、現在も残っている読者 |
| **エピソードを読んだか購入した** | そのうち、集計済みのいずれかの日にエピソードを閲覧した、読み終えた、または購入した読者 |
| **7日以内に購入した** | そのうち、アカウントの作成から7日未満で初めて購入した読者 |
| **30日以内に購入した** | 同じく30日以内 |
| **購入した** | そのうち、一度でも購入した読者 |

**登録者に占める割合**は、それぞれの数を**登録した**で割った値です。「**初回購入までの日数（中央値）**」は、購入した読者について、アカウントの作成から初回購入までの日数の中央値で、購入した読者がいるまでは`—`です。購入は行われた時点ですぐに数え、返金されたものも含みますが、ストアのサンドボックスや決済プロバイダのテストモードで行われた購入は数えません。

削除されたアカウントは、その行とそれに基づくすべての数からすぐに外れます。これらの画面が数える閲覧と購入は、インストール環境がそれを記録し始めた日から保持されています。**コホート**を追加したリリースにアップグレードしたインストール環境では、アップグレードの時点でまだ保持されていたアナリティクスのイベントのうち最も古い日がその日です。それより前の週には、その週に登録した読者は表示されますが、その読者の行動は表示されず、後から埋まることもありません。

![1週分、3人の読者の登録週ごとの継続率。全員が0週目にアクティブで、1週目と2週目には3分の1がアクティブ。その下に、各段階の読者、登録者に占める割合、初回購入までの日数の中央値を示すファネル。](./reports-and-royalties-cohorts.png)

### レポートをCSVでダウンロードする

**売上**、**読者の反応**、**離脱**の表の横にある**CSVをダウンロード**は、画面に表示されている期間のその表のレポートを、表と同じく日別、シリーズ別、またはエピソード別でダウンロードします。ファイルには、表の並び順にかかわらず、レポートのすべての行がレポートの順序で含まれます。日付は順に、**売上**のシリーズやエピソードは純売上の多い順に、**読者の反応**のシリーズはフォロワーの多い順に、離脱のページは順に並びます。**エピソード**の**読了率**と**コホート**にはダウンロードはありません。

ファイル名は、レポート、テナント、期間から付けられ、`revenue-by-series-<tenant>-2025-03-03--2025-03-09.csv`のようになります。離脱では`drop-off-<tenant>-<episode>-<from>--<to>.csv`です。ファイルはUTF-8で、Excelが正しく読めるようにバイトオーダーマークが付き、ヘッダー行の下にレポートの行ごとに1行があり、合計の行はありません。列は次のとおりです。

| レポート | 列 |
| --- | --- |
| 日別の売上 | `date`, `purchase_count`, `gross_amount`, `refunded_amount`, `net_amount`, `currency` |
| シリーズ別の売上 | `start_date`, `end_date`, `series_id`, `series_title`, `purchase_count`, `gross_amount`, `refunded_amount`, `net_amount`, `currency` |
| エピソード別の売上 | `start_date`, `end_date`, `series_id`, `series_title`, `episode_id`, `episode_title`, `purchase_count`, `gross_amount`, `refunded_amount`, `net_amount`, `currency` |
| 日別の読者の反応 | `date`, `follower_count`, `followed_count`, `unfollowed_count`, `view_count`, `complete_count`, `reaction_count`, `reaction_points` |
| シリーズ別の読者の反応 | `start_date`, `end_date`, `series_id`, `series_title`, `follower_count`, `followed_count`, `unfollowed_count`, `view_count`, `complete_count`, `reaction_count`, `reaction_points`, `rating_average`, `rating_count` |
| 離脱 | `start_date`, `end_date`, `episode_id`, `page_index`, `reader_count` |

`date`、`start_date`、`end_date`はテナントの日付で、`YYYY-MM-DD`形式です。後の2つはダウンロードの期間で、すべての行で同じです。金額は通貨の最小単位で、JPYなら円、USDならセントです。`currency`はテナントの通貨です。`rating_average`は小数1桁で、どの読者も評価していないシリーズでは`0.0`です。`page_index`は最初のページを`0`として数え、`reader_count`はそのページに到達した読者の数です。タイトルはテナントの既定の言語で、IDによって、名前が変わっても行がシリーズやエピソードと結び付いたままになります。スプレッドシートが数式として読むセルは、テキストのままになるように書き出されます。

レポートはダウンロードした時点で読み取られるため、今日を含む期間では、後でダウンロードすると数値が異なることがあります。各ダウンロードは**監査ログ**に**アナリティクスのCSVダウンロード**として記録されます。

## 印税

**印税**は、各著者がクレジットされているエピソードの売上について、その著者に支払うべき金額を月ごとに計算します。月は締めるまで開いたままで、その数値はあらゆる販売、返金、取り分の変更に追随します。締めると、以後変わらない明細が作成されます。テナントは明細に基づいて著者に支払います。Publiraは誰にも支払いを行わず、明細は支払うべき金額の記録です。

### 著者に支払うべき金額

著者には、クレジットされている各エピソードの取り分が支払われます。取り分はクレジットに、エピソードの売上に対するパーセントとして設定し、エピソードの取り分を除いた残りは出版社のものになります。

- **シリーズのフォーム**では、**著者**で各クレジットの取り分を**著者（番号）の取り分**に設定します。これらのクレジットは新しいエピソードを作成するときのひな形で、変更しても既存のエピソードはそのままです。
- **エピソード**では、**著者**でそのエピソード自身のクレジットと取り分を変更し、**著者を保存**で保存します。
- **シリーズのエピソード一覧**では、**クレジット** › **取り分を設定**で、多数のエピソードにある1つのクレジットの取り分を一度に変更します。

取り分は0から100パーセントで、小数点以下2桁まで指定でき、1つのエピソードの取り分の合計は100以下です。取り分が0の場合、著者はクレジットされますが支払いはありません。編集担当は作品を編集するため、取り分も設定できます。

各クレジットについて、1か月の支払額は次のとおりです。

> （その月のエピソードの売上 − その売上に対する返金）× 取り分。円やセントなど、テナントの通貨の最小単位に切り捨て

1か月の売上は次のとおりです。

- サイトでStripeまたはPAY.JPを通じて行われたエピソードの購入。読者が支払った価格で数えます。
- そのエピソードを含む巻のサイトでの購入。それぞれ、読者が支払った価格のうちそのエピソードの部分での、エピソードの販売です。価格は、購入が記録された時点での巻の各エピソード自身の価格に比例して、どのエピソードにも価格がない場合は均等に配分されます。そのため、価格付きのエピソードがある巻の無料エピソードには配分がなく、販売もありません。配分は購入時に確定し、その後にエピソードの価格を変えたり巻の内容を変えたりしても変わりません。巻の一部返金も同じ比率で配分され、各エピソードの部分は切り捨てられます。
- シリーズの残りのエピソードのサイトでの購入。それぞれ、読者が支払った価格のうちの各部分での、それで読めるようになった各エピソードの販売です。各エピソードの部分は、読者が決済を始めた時点で確定します。まとめ買い割引は、エピソードが販売された価格（キャンペーン中はキャンペーン価格）に比例して各エピソードに配分されるため、後でエピソードの価格やシリーズの割引を変更しても変わりません。プロモーションコードによって読者が決済の価格より少なく支払った場合は、各部分が同じ比率で減らされます。一部返金は価格と同じ比率で配分され、各エピソードの部分は切り捨てられます。
- テナントのアプリでのApp StoreまたはGoogle Playを通じた購入。エピソードの価格で数えます。ストアの手数料は差し引きません。
- サイトまたはアプリでの、テナントのコインによるエピソードの購入。使ったコインに支払われた金額で数えます。パックのコイン1枚の価値は、ボーナスコインを含めて、読者がパックに支払った金額を等分したものです。そのため、ボーナスはテナントが行う割引になります。1,100コイン（うち100コインがボーナス）のパックを1,000円で購入すると、コイン1枚の価値は0.909円になり、100コインのエピソードは通貨の最小単位に切り捨てて90円の販売になります。支払いなしで付与されたコインの価値は0で、テスト購入のコインや、テナントの現在の通貨とは別の通貨で支払われたパックのコインも同様です。販売の価値はコインを使った時点で確定し、その後にパックを編集しても変わりません。

金額はすべてテナントの通貨で、締めた明細は締めたときの通貨を保持します。別の通貨で支払われた購入は、テナントが通貨を変更する前に始めた支払いを読者が完了した場合にだけ起こります。この購入でエピソードは読めるようになりますが、明細上の販売にはなりません。

これら以外は販売ではありません。コインのパックの購入は販売ではなく、その代金は、コインが使われるにつれてそのコインによる販売になります。アクセスチケット、**待てば無料**、無料公開期間、著者が自分のエピソードを読むことでは、販売なしでエピソードが読めるようになります。App Storeのサンドボックスや、Playのライセンステスターによる購入、StripeやPAY.JPのテスト用のキーで行われた購入はテストで、除外されます。

全額返金された購入は、購入した月から外れます。一部返金では販売はそのまま残り、その金額は**返金**として差し引かれます。どちらの場合も、購入した月が開いているあいだは、返金は返金した月ではなく購入した月に計上されます。

読者のカード会社がテナント側に不利な判断をした[異議申し立て](./4-selling-episodes.md#異議申し立て)のStripeの支払いは、Stripeがその判断を報告した時点から、ここでも締めた後でも全額返金として数えます。まだ結論の出ていない異議申し立てや、テナント側に有利な判断が出た異議申し立てでは、販売はそのまま残ります。

コインのパックが全額返金されたり異議を申し立てられたりすると、使われたコインで支払った各購入について、そのコインの価値分が返金されます。読者は読めるようになったエピソードをそのまま読めるため、各購入は販売のまま残り、その金額が**返金**に入ります。購入に使ったコインがすべてそのパックのものなら価格の全額が、一部が別のパックのものならそのパックの分が入ります。ほかの返金と同じく、購入した月が開いているあいだはその月に計上され、締めた後は次の明細から差し引かれます。

### 締めた後の返金

購入した月を締めた後に記録された返金では、その明細を変更できません。代わりに、その後に締める次の明細から、調整の明細行として差し引かれます。調整の行は、販売を計上した締め済みの行と同じ著者、シリーズ、エピソード、役割の下にあり、調整の対象となる締め済みの月が示されます。調整はその月自体の明細行の後に来ます。その数値は変化分なので、販売の行で正になる値は負になります。

- **販売数**は全額返金された購入の数のマイナス、**売上**はその価格のマイナスです。
- **返金**は、販売のまま残っている購入の返金の変化分です。締めた時点で一部返金されていた購入が、その後全額返金された場合は負になります。その購入は今度は**売上**を通じて外れるためです。
- **支払額**は、返金によって締め済みの行の支払額から差し引かれる額です。行の支払額を、締めた月に適用した取り分で、以前と同じく切り捨てて、残った販売に対して計算し直し、そこから元の支払額を引いた額です。締めた後に取り分を変更したり著者をクレジットしたりしても、この額は変わりません。締め済みの行とその調整を合わせると、返金が締める前に来ていた場合にその行が支払ったはずの額になります。そのため、行のすべての販売が返金されると、支払いは0になります。

返金のどの部分も、差し引かれるのは1回だけです。ある締めの後に一部返金され、次の締めの後に全額返金された購入は、2回の調整で差し引かれます。2回目は1回目で差し引かなかった分で、明細を合わせるとその購入への支払いは0になります。

調整が繰り越されるのは、調整の対象となる月より後の月だけです。より前の月より先に、順番どおりでなく締めた月には、そのより前の月の返金は繰り越されず、両方の後に締める次の月に繰り越されます。ある月の調整がその月自体の売上を上回ると、その月の**著者への支払額**は負になり、著者の調整がその著者の販売の行を上回ると、その著者の小計も負になります。

### 未締めの月を確認する

**印税**は、最新の締めた明細の翌月を、まだ何も締めていない場合は先月を開きます。**月**で月を選んで**表示**を押すと、締めておらず、すでに始まっているほかの月を開けます。

**未締めの月**には4つの合計があります。

| 合計 | 内容 |
| --- | --- |
| **売上** | その月のすべての販売を価格で合計したもので、著者がクレジットされていないエピソードの販売も含みます |
| **返金** | それらの販売に対する返金 |
| **返金の調整** | [締めた後の返金](#締めた後の返金)で説明するとおり、締めた後に返金された締め済みの月の販売について、その月が差し戻す額です。各販売は1回だけ数えます。0か負の金額です |
| **著者への支払額** | その月が著者に支払うべき額で、調整を含む下の明細行の合計です。**売上**から**返金**と**返金の調整**を引いた残りは出版社のものです |

**著者ごとの明細**では、その月が著者ごとにまとめられ、その月に売れたエピソードの各クレジットに1行と、著者ごとの**小計**があります。各行には、**シリーズ**、**エピソード**、クレジットの**役割**、**販売数**、**売上**の金額、**返金**の金額、**分配率**、**支払額**が表示されます。同じエピソードに2つの役割でクレジットされている著者には、それぞれの行があります。調整は、その著者のまとまりの中でその月自体の行の後に来て、エピソードの下に「**（月）分の返金の調整**」として締め済みの月が示され、著者の**小計**に含まれます。

合計の上には、その月の状態が表示されます。

- **この月はまだ進行中です。** テナントのタイムゾーンでその月の最終日が終わると締められます。
- **この月は終わっており、締められます。** **月を締める**で締めます。
- **この月は（日付）に自動で締められます。** その日付に`publira worker`が月を締め、管理画面には手動で締める手段はありません。

![2026年1月の印税。上部に締めた明細と締めの設定、表示ボタン付きの月の欄、未締めの月の売上、返金、返金の調整、著者への支払額、月を締めるボタンのある「この月は終わっており、締められます。」、各著者の明細行と小計がある著者ごとの明細。](./reports-and-royalties-open-month.png)

### 月を締める前に

月を締めると、その時点の状態で確定し、その後に起きたことは反映されません。締める前に次の点を確認してください。

- **クレジットと取り分。** 明細では、エピソードが売れたときではなく、月を締めた時点での各取り分が使われます。締める前に取り分を変更すると、その月全体が新しい取り分で支払われます。締めた後に変更すると、新しい取り分が適用されるのは未締めの月だけです。
- **見込まれる返金。** [締めた後の返金](#締めた後の返金)で説明するとおり、締めた後に記録された返金は、締めた月ではなく次の明細から差し引かれます。そのため、著者にはいったんその販売の分が支払われ、支払額は後の月から差し戻されます。返金が来るとわかっている場合は、それが購入した月に計上されるように待ってください。
- **月が終わっていること。** 最終日の遅い時間に行われた販売は、テナントのタイムゾーンで数えます。それはあなたのタイムゾーンとは異なるかもしれません。

月は順番に締めてください。管理画面が最新の明細の翌月を表示するのはこのためで、飛ばした月を後で締めるには**月**で選ぶ必要があります。

### 月を締める

1. **レポート** › **印税**を開きます。表示されている月が、次に締める月です。
2. 「**この月は終わっており、締められます。**」と表示されていることを確認し、**著者ごとの明細**に目を通します。
3. **月を締める**を選びます。確定する**著者への支払額**がダイアログに表示されます。もう一度**月を締める**を選んで確定します。

![月を締めるダイアログ。確定する著者への支払額と、キャンセルと月を締めるボタン。](./reports-and-royalties-close-month.png)

その後、管理画面はその月の**明細**を開きます。明細には、「**（日時）に（名前）が締めました。**」として締めた日時と締めた人が表示され、未締めの月にあったのと同じ合計と明細行が表示されます。締めは**監査ログ**に**印税の月締め**として記録されます。

![2025年12月の明細。締めた日時、締めた人、区切ったタイムゾーン、合計、CSVをダウンロード、締めた時点での各著者の明細行。](./reports-and-royalties-statement.png)

締めた明細は、各著者、シリーズ、エピソード、役割の名前を締めた時点のまま保持します。その後に著者の名前を変えたり、取り分を編集したり、購入を返金したり、クレジットを削除したりしても、明細はそのままです。その後に記録された返金は、代わりに次の明細から差し引かれます。締めた月は、スタッフもオペレーターも再び開くことはできません。後で見つかった誤りは、テナントが支払う額の中で、Publiraの外で訂正してください。

**締めた明細**には、締めたすべての月が新しい順に、締めた日時、締めた人、合計とともに表示されます。自動で締めた月では、**締めた人**に`—`と表示されます。

![締めた明細。テナントの管理者が2026年1月5日に締めた2025年12月の、売上、返金、返金の調整、著者への支払額と、CSVをダウンロード。](./reports-and-royalties-closed-statements.png)

### 明細をCSVで書き出す

**CSVをダウンロード**は、締めた明細をダウンロードします。**明細**の画面自体か、**締めた明細**の各行から行えます。未締めの月は数値がまだ変わり続けるため、ダウンロードできません。

ファイル名は`royalties-<tenant>-<YYYY-MM>.csv`です。ファイルはUTF-8で、Excelが正しく読めるようにバイトオーダーマークが付き、ヘッダー行の下に明細の行ごとに1行があり、合計の行はありません。列は次のとおりです。

| 列 | 内容 |
| --- | --- |
| `period` | 月。`YYYY-MM`形式 |
| `creator_id`, `creator_name` | 著者 |
| `role_id`, `role_name` | クレジットの役割。役割のないクレジットでは空です |
| `series_id`, `series_title` | シリーズ |
| `episode_id`, `episode_title` | エピソード |
| `sale_count` | 販売数 |
| `gross_amount` | 売上。明細の通貨の最小単位で、JPYなら円、USDならセントです |
| `refunded_amount` | 売上に対する返金。単位は同じです |
| `share_percent` | 取り分。`12.50`のように小数2桁です |
| `payout_amount` | 支払額。単位は同じです |
| `currency` | `USD`のような明細の通貨です。月を締めたときのテナントの通貨で、明細が売上を数えるのはこの通貨だけです |
| `adjusted_period` | その月自体の販売の行では空です。調整の行では、返金を差し戻す対象の締め済みの月が`YYYY-MM`形式で入り、金額は[締めた後の返金](#締めた後の返金)で説明する負の変化分です |

名前は締めた時点のもので、IDによって、名前が変わっても行が著者やエピソードと結び付いたままになります。スプレッドシートが数式として読むセルは、テキストのままになるように書き出されます。明細は毎回同じファイルをダウンロードし、各ダウンロードは**監査ログ**に**印税明細のCSVダウンロード**として記録されます。

### 月を自動で締める

**印税**の**締めの設定**で、月の締め方を選びます。

- **毎月自分で締める**（既定）：テナント管理者が上の手順で締めるまで、月は開いたままです。
- **自動で締める**：各月は、翌月の**締め日**に締められます。締め日はテナントのタイムゾーンでの1日から28日のいずれかです。

**締めの設定を保存**を選ぶと選択が適用され、変更は**監査ログ**に**印税の締めの設定更新**として記録されます。

![締めの設定。自動で締めるではなく毎月自分で締めるが選ばれており、締めの設定を保存がある。](./reports-and-royalties-closing-settings.png)

自動の締めは、締め日の午前0時を過ぎた後の`publira worker`の最初の1時間ごとの処理で行われ、**月を締める**とまったく同じように月を締め、**締めた人**には誰も記録しません。締め日にワーカーが止まっていた場合は、再び動き出したときに、締めるべき月を古い順に締めます。`publira worker`が動いていなければ、どの月も自動では締められません。

**自動で締める**は、選んだ後に終わる月に適用されます。切り替えた時点ですでに終わっている月は手動で締めることになるので、上の手順で**印税**から締めてください。締める前に誰にも確認されないため、[月を締める前に](#月を締める前に)の確認を行う時間が取れる**締め日**を選び、取り分は締め日の後ではなく前に直してください。

インストールは、読者、各テナントのスタッフ、プラットフォーム管理画面のオペレーターにメールを送ります。メールはどれも、運用者が用意したSMTPサーバーを通して`publira worker`が送ります。プラットフォームのSMTPアカウントは`publiractl setup`で保存済みで、テナントは独自のアカウントを保存することもできます。このページでは、この2つのアカウントとそのテスト方法、メールの見た目とリンク先を決める設定を説明します。

このページの`publiractl`コマンドは、コマンドの部分だけを示しています。[プラットフォーム管理画面とpubliractl](./1-platform-console.md#どちらを使うか)の説明に従い、`PUBLIRA_PLATFORM_DB_URL`に`publira_platform`の接続先を設定して実行してください。`PUBLIRA_SECRET_ENCRYPTION_KEYS`と`PUBLIRA_SECRET_ENCRYPTION_PRIMARY_KEY_ID`には、各プロセスと同じ値を設定します。フラグの一覧は[`publiractl`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#smtp)にあります。

## Publiraが送るメール

| 宛先 | メール |
| --- | --- |
| テナントの読者 | 新しいアカウントのメールアドレスを確認するリンク、パスワードの再設定とパスワード変更のお知らせ、新しいメールアドレスの確認と古いアドレスへの変更のお知らせ、登録済みのアドレスで誰かが会員登録しようとしたことのお知らせ、お問い合わせへのスタッフの返信、フォロー中のシリーズや著者の新しいエピソード、テナントが投稿したお知らせ、コメントの承認 |
| テナントのスタッフ | テナントの管理者への招待、パスワードの再設定、新しいメールアドレスの確認と古いアドレスへのお知らせ、読者からの新しいお問い合わせ |
| プラットフォームのオペレーター | パスワードの再設定、新しいメールアドレスの確認と古いアドレスへのお知らせ |

メールはテナントの既定言語で書かれます。オペレーターあてのメールは、プラットフォームの既定言語で書かれます。

読者あての最後の3つ、つまり新しいエピソード、お知らせ、コメントの承認は、読者の通知設定に従って届きます。通知の種類ごとにメールの設定があり、読者がオフにしない限りオンです。また、届くのは確認済みのアドレスだけです。ただし、テナントが全員に送るお知らせは、設定にかかわらず、確認済みのアドレスを持つすべての読者にメールで届きます。読者の多いテナントでは、その人数分のメールが一度にSMTPアカウントから送られることになります。

ワーカーはどのメールもいったんキューに入れ、送れなかったメールは再試行します。待ち時間は失敗するたびに1秒、2秒、4秒と倍になっていきます。最初の試行から約9分後、10回目の試行にも失敗すると、ワーカーはそのメールを完全にあきらめ、それ以降は誰も送りません。そのため、SMTPサーバーがそれより長く止まると、そのあいだにキューに入ったメールは遅れて届くのではなく失われます。`email-renderer`を有効にしている場合は、`email-renderer`が止まったときも同じです。試行回数は`publira worker`の`PUBLIRA_OUTBOX_MAX_ATTEMPTS`で変えられます。待ち時間は試行の間隔が最大1時間になるまで倍になり続けるので、試行回数を少し増やすだけで、ずっと長い停止にも耐えられます。

あきらめたメールは、ワーカーが`outbox event dead`としてログに記録します。ワーカーがOpenTelemetryのメトリクスを出力していれば、`publira.outbox.events.dead`メトリクスにも数えられるので、どちらかにアラートを設定してください。インストールがこうしたメールを送り直すことはできません。パスワードの再設定や確認のメールは読者にもう一度依頼してもらい、管理者への招待は[テナントのスタッフ](./3-tenant-staff.md)で説明するとおり再送します。

ワーカーが動いていないインストールでは、メールは一切送られません。

## メールを送るSMTPアカウント

| メール | 送信に使うアカウント |
| --- | --- |
| テナントが読者とスタッフに送るメール | テナントが独自のSMTPアカウントを保存して有効にしていればそのアカウント、そうでなければプラットフォームのアカウント |
| プラットフォーム管理画面のメール | 常にプラットフォームのSMTPアカウント |

プラットフォームのアカウントは必須です。ないと、どのオペレーターもパスワードを再設定できず、独自のアカウントを持たないテナントはどれもメールを送れません。テナント独自のアカウントは任意で、自社のドメインから自社のプロバイダーでメールを送りたい出版社のためのものです。

## プラットフォームのSMTPアカウント

| 設定 | `publiractl smtp set` | プラットフォーム管理画面 |
| --- | --- | --- |
| SMTPサーバー | `--host`と`--port` | **ホスト**と**ポート** |
| 接続の暗号化方式 | `--encryption`に`tls`、`starttls`、`none`のいずれかを指定 | **暗号化方式**で**TLS**、**STARTTLS**、**なし**のいずれかを選択 |
| ログインに使うユーザー | `--username` | **ユーザー名** |
| そのユーザーのパスワード | `--password-file`、`--password-stdin`、入力を伏せたプロンプトのいずれか(プラットフォームがシークレットを環境変数でしか渡せない場合は`--password-env`) | **パスワード** |
| メールの送信元アドレス | `--from-address` | **送信者メールアドレス** |
| 送信元と異なる場合の返信先アドレス | `--reply-to` | **返信先メールアドレス(任意)** |

![メール設定。ホスト、ポート、ユーザー名、パスワード、暗号化方式、送信者メールアドレス、返信先メールアドレス(任意)の各欄と、接続テストボタン、保存ボタンがある。](./email-smtp-settings.png)

値は、メールプロバイダーがSMTPでの送信用に案内しているものを使ってください。ポート587はほぼ必ずSTARTTLSで、ポート465は接続の最初からTLSです。**なし**を選ぶのは、自社のプライベートネットワーク内にあるリレーを使うときだけにしてください。

ログインせずにメールを受け付けるリレーを使うときは、ユーザー名を空にします。ワーカーは認証せずに送り、パスワードは保存されません。パスワードはインストールの暗号化キーで暗号化して保存されるので、`publira worker`は保存したときと同じ暗号化キーで動かす必要があります。

送信元アドレスは、プロバイダーがそのアカウントでの送信を認めているアドレスにします。また、自社のドメインで、プロバイダーが求めるSPFとDKIMのレコードを公開してください。そうしないと、メールの多くが迷惑メールに振り分けられたり、読者のメールサーバーに拒否されたりします。

### アカウントをテストする

テストでは、アカウントから短いメッセージを1通送り、サーバーが受け付けたかどうかを表示します。

- プラットフォーム管理画面では、**メール**の**接続テスト**を選ぶと**SMTP接続テスト**が開きます。保存する前のフォームの値で、**自分に送信する**なら自分あてに、そうでなければ**送信先メールアドレス**あてに送ります。送信は`publira server`から行われます。
- `publiractl smtp test --to operator@example.com`は、保存済みの設定を使い、`publiractl`を実行したマシンから送ります。サーバーが受け付けなければ、終了コード`1`で終了します。

![SMTP接続テストのダイアログ。自分に送信するにチェックが入っていて、閉じるボタンとテストを実行ボタンがある。](./email-connection-test.png)

サーバーが受け付けても、テストメッセージが迷惑メールに振り分けられていることがあります。送った先のメールボックスで確認してください。また、テストを送るのは`publira server`か`publiractl`ですが、実際のメールを送るのは`publira worker`です。ワーカーからもSMTPサーバーに届くことを確かめておいてください。

### 設定を変更する

プラットフォーム管理画面で、サイドバーの**外部サービス**にある**メール**を選び、値を変更して**保存**を選びます。保存済みのパスワードは、横の**変更する**を選ばない限り残ります。**変更する**を選んだうえで欄を空にして保存すると、パスワードは削除されます。保存できるのはオペレーターとスーパー管理者で、監査担当は画面を閲覧できるだけです。

![パスワードを保存した状態のユーザー名とパスワードの欄。パスワードは伏せて表示され、その下に変更するがある。](./email-saved-password.png)

`publiractl`では、次のように操作します。

```bash
publiractl smtp set \
  --host smtp.example.com --port 587 --encryption starttls \
  --username mailer --password-file /run/secrets/smtp-password \
  --from-address no-reply@example.com
publiractl smtp test --to operator@example.com
publiractl smtp show
```

`smtp set`は、保存済みの設定を、指定したフラグの値ですべて置き換えます。たとえば`--reply-to`を省略すると保存済みの返信先が消えるので、毎回すべてを指定してください。保存済みと同じ`--username`をパスワードなしで指定すると、保存済みのパスワードはそのまま残ります。

ワーカーはメールを送るたびに設定を読むので、保存した設定は再起動しなくても次のメールから使われます。保存もテストも、そのたびに**監査ログ**に記録されます。

## テナント独自のSMTPアカウント

テナント独自のアカウントは、テナントの管理者がテナント管理画面の**外部連携** › **メール情報**で設定します。**テナントSMTP上書きを有効にする**の**上書きを有効化**をオンにして、プラットフォームのアカウントと同じ項目と**送信者名(任意)**を入力します。**接続テスト**はフォームの値でテストメッセージを送り、**保存**は設定を保存します。変更できるのはテナント管理者だけで、手順は[メール](../4-console/3-setup/7-email.md)で説明しています。

保存した次のメールから、そのテナントのメールは、新しい管理者への招待も含めてすべてテナントのアカウントから送られます。上書きをオフにすると、再びプラットフォームのアカウントから送られます。

オペレーターが設定することは何もありません。プラットフォーム管理画面からも`publiractl`からも、テナントのアカウントは変更できません。プラットフォームのアカウントのテストは成功するのに、あるテナントのメールが届かなくなったときは、まずそのテナント独自のアカウントを確認してください。

## プレーンテキストとHTML

`email-renderer`がなければ、メールはすべてプレーンテキストです。`email-renderer`を使うと、どのメールにも同じテキストと並んでHTML版が入り、読者のメールアプリが好きなほうを表示します。有効にするには、[email-rendererによるHTMLメール](../2-deployments/2-installing.md#email-rendererによるhtmlメール)で説明するとおり、`email-renderer`を動かして、`PUBLIRA_EMAIL_RENDERER_URL`で`publira worker`にその場所を指定します。

有効にすると、`email-renderer`はメール送信の一部になります。`email-renderer`が止まっているあいだ、ワーカーはメールをテキストだけで送ることはせず、SMTPサーバーが止まったときと同じ試行回数の範囲で再試行します。そのため、`email-renderer`がそれより長く止まると、やはりメールは失われます。プレーンテキストに戻すには、この環境変数を削除してワーカーを再起動します。

## メールのリンク先

ほとんどのメールには、メールアドレスの確認、パスワードの再設定、招待の承諾といったリンクが入っています。ワーカーは、リクエストがどのホスト名で届いたかを知らないままリンクを組み立てるので、ホスト名とスキームは`publira worker`が読むインストールの設定で決まります。

| メール | リンク先 |
| --- | --- |
| 読者あて | テナントのドメイン(`https://comics.example.com`など) |
| テナントのスタッフあて | テナントの管理画面のホスト名(別のホスト名を指定していなければ`admin.<domain>`) |
| プラットフォームのオペレーターあて | `PUBLIRA_PLATFORM_APP_URL`のアドレス(`https://platform.example.com`など) |

テナントのリンクのスキームは`PUBLIRA_TENANT_URL_SCHEME`で決まり、設定しなければ`https`です。`http`にするのは、ブラウザーが実際にHTTPでテナントを開く場合だけにしてください。プラットフォーム管理画面を動かすインストールでは、`publira worker`に必ず`PUBLIRA_PLATFORM_APP_URL`を設定してください。設定しないと、オペレーターあてのリンクがローカルの開発マシンのアドレスを指してしまいます。

テナントのリンクはドメインに従います。[テナントを別のホスト名に移す](./2-tenants.md#テナントを別のホスト名に移す)で説明するとおり、テナントを別のホスト名に移すと、それ以降に送るメールのリンクは新しいホスト名を指し、それまでに送ったメールのリンクは古いホスト名を指したままです。

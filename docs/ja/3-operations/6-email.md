Publiraは、読者、各テナントのスタッフ、プラットフォーム管理画面のオペレーターにメールを送ります。メールはすべて`publira worker`が、運用者が用意したSMTPサーバーを通して送ります。プラットフォームのSMTPアカウントは`publiractl setup`で保存済みで、テナントは独自のアカウントを保存することもできます。このページでは、この2種類のアカウントとそのテスト方法、メールの表示形式とリンク先を決める設定を説明します。

このページの`publiractl`コマンドは、コマンド部分だけを示しています。実行するときは[プラットフォーム管理画面とpubliractl](./1-platform-console.md#どちらを使うか)の説明に従い、`PUBLIRA_PLATFORM_DB_URL`に`publira_platform`への接続先を設定してください。`PUBLIRA_SECRET_ENCRYPTION_KEYS`と`PUBLIRA_SECRET_ENCRYPTION_PRIMARY_KEY_ID`にも、各プロセスと同じ値を設定します。すべてのフラグは[`publiractl`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#smtp)に載っています。

## Publiraが送るメール

| 宛先 | メール |
| --- | --- |
| テナントの読者 | 新しいアカウントのメールアドレスを確認するリンク、パスワードの再設定とパスワード変更のお知らせ、新しいメールアドレスの確認と古いアドレスへの変更のお知らせ、登録済みのアドレスで誰かが会員登録しようとしたことのお知らせ、お問い合わせへのスタッフの返信、フォロー中のシリーズや著者の新しいエピソード、テナントが投稿したお知らせ、コメントの承認 |
| テナントのスタッフ | テナントの管理者への招待、パスワードの再設定、新しいメールアドレスの確認と古いアドレスへのお知らせ、読者からの新しいお問い合わせ |
| プラットフォームのオペレーター | パスワードの再設定、新しいメールアドレスの確認と古いアドレスへのお知らせ |

メールは、テナントの既定言語で書かれます。オペレーターあてのメールは、プラットフォームの既定言語で書かれます。

読者あての最後の3つ、つまり新しいエピソード、お知らせ、コメントの承認は、読者の通知設定に従って届きます。通知の種類ごとにメールの設定があり、読者がオフにしない限りオンです。届くのは確認済みのアドレスだけです。ただし、テナントが全員に送るお知らせは、設定にかかわらず、確認済みのアドレスを持つすべての読者にメールで送られます。読者の多いテナントでは、その人数分のメールが一度にテナントのSMTPアカウントから送られることになります。

ワーカーはメールをすべてキューに入れ、送れなかったメールを再試行します。待ち時間は失敗するたびに1秒、2秒、4秒と倍になります。10回目の試行にも失敗すると、ワーカーはそのメールをあきらめます。最初の試行から約9分後で、それ以降そのメールが送られることはありません。そのため、SMTPサーバーが止まっている時間がこれより長いと、その間にキューに入ったメールは遅れて届くのではなく失われます。`email-renderer`を有効にしている場合は、`email-renderer`が止まったときも同じです。試行回数は`publira worker`の`PUBLIRA_OUTBOX_MAX_ATTEMPTS`で変えられます。待ち時間は試行の間隔が最大1時間になるまで倍になり続けるので、試行回数を少し増やすだけで、ずっと長い停止に耐えられるようになります。

ワーカーはあきらめたメールを`outbox event dead`としてログに記録します。ワーカーがOpenTelemetryのメトリクスを出力していれば、`publira.outbox.events.dead`メトリクスにも数えられます。どちらかを監視してアラートを出すようにしてください。Publiraはあきらめたメールを送り直せません。パスワードの再設定や確認のメールは読者がもう一度依頼し、管理者への招待は再送します。招待の再送は[テナントのスタッフ](./3-tenant-staff.md)で説明しています。

ワーカーが動いていなければ、メールは一切送られません。

## メールを送るSMTPアカウント

| メール | 送信に使うアカウント |
| --- | --- |
| テナントが読者とスタッフに送るメール | テナントが独自のSMTPアカウントを保存して有効にしていればそのアカウント。それ以外はプラットフォームのアカウント |
| プラットフォーム管理画面のメール | 常にプラットフォームのSMTPアカウント |

プラットフォームのアカウントは必須です。これがないと、オペレーターは誰もパスワードを再設定できず、独自のアカウントを持たないテナントはどれもメールを送れません。テナント独自のアカウントは任意です。自社のドメインから自社のプロバイダーでメールを送りたい出版社のためのものです。

## プラットフォームのSMTPアカウント

| 設定 | `publiractl smtp set` | プラットフォーム管理画面 |
| --- | --- | --- |
| SMTPサーバー | `--host`、`--port` | **ホスト**、**ポート** |
| 接続の暗号化方式 | `--encryption`に`tls`、`starttls`、`none`のいずれかを指定 | **暗号化方式**で**TLS**、**STARTTLS**、**なし**のいずれかを選択 |
| ログインに使うユーザー | `--username` | **ユーザー名** |
| そのユーザーのパスワード | `--password-file`、`--password-stdin`、入力を伏せたプロンプトのいずれか。プラットフォームがシークレットを環境変数でしか渡せない場合は`--password-env` | **パスワード** |
| メールの送信元アドレス | `--from-address` | **送信者メールアドレス** |
| 送信元と異なる場合の返信先アドレス | `--reply-to` | **返信先メールアドレス（任意）** |

![メール設定。ホスト、ポート、ユーザー名、パスワード、暗号化方式、送信者メールアドレス、返信先メールアドレス（任意）の各欄と、接続テストボタン、保存ボタンがある。](./email-smtp-settings.png)

値は、メールプロバイダーがSMTPでの送信用に案内しているものを使ってください。ポート587はほぼ必ずSTARTTLSで、ポート465は接続の最初からTLSです。**なし**を選ぶのは、自社のプライベートネットワーク内のリレーを使う場合だけにしてください。

ログインせずにメールを受け付けるリレーを使う場合は、ユーザー名を空にします。ワーカーは認証せずに送信し、パスワードは保存されません。パスワードはPubliraの暗号鍵で暗号化して保存されるので、`publira worker`は保存したときと同じ暗号鍵を設定して動かす必要があります。

送信元アドレスには、プロバイダーがそのアカウントでの送信を認めているアドレスを使います。また、自社のドメインには、プロバイダーが求めるSPFとDKIMのレコードを公開してください。そうしないと、メールの多くが迷惑メールに振り分けられたり、読者のメールサーバーに受け取りを拒否されたりします。

### アカウントをテストする

テストでは、アカウントから短いメッセージを1通送り、サーバーが受け付けたかどうかを表示します。

- プラットフォーム管理画面では、**メール**の**接続テスト**を選ぶと**SMTP接続テスト**が開きます。保存する前のフォームの値で、**自分に送信する**なら自分あてに、そうでなければ**送信先メールアドレス**に入力したアドレスあてに送ります。送信は`publira server`から行われます。
- `publiractl smtp test --to operator@example.com`は、保存済みの設定で、`publiractl`を実行したマシンから送ります。サーバーが受け付けなければ終了コード`1`で終了します。

![SMTP接続テストのダイアログ。自分に送信するにチェックが入っていて、閉じるボタンとテストを実行ボタンがある。](./email-connection-test.png)

サーバーがテストメッセージを受け付けても、迷惑メールに振り分けられていることがあります。送ったメールボックスで届き方を確認してください。また、テストを送るのは`publira server`か`publiractl`で、実際のメールを送るのは`publira worker`です。ワーカーからもSMTPサーバーに接続できることを確かめておいてください。

### 設定を変更する

プラットフォーム管理画面で、サイドバーの**外部サービス**にある**メール**を選び、値を変更して**保存**を選びます。保存済みのパスワードは、横の**変更する**を選ばない限りそのまま残ります。**変更する**を選んでから欄を空にして保存すると、パスワードは削除されます。保存できるのはオペレーターとスーパー管理者で、監査担当は画面を閲覧できるだけです。

![パスワードを保存した状態のユーザー名とパスワードの欄。パスワードは伏せて表示され、その下に変更するがある。](./email-saved-password.png)

`publiractl`では次のように操作します。

```bash
publiractl smtp set \
  --host smtp.example.com --port 587 --encryption starttls \
  --username mailer --password-file /run/secrets/smtp-password \
  --from-address no-reply@example.com
publiractl smtp test --to operator@example.com
publiractl smtp show
```

`smtp set`は、保存済みの設定を指定したフラグの値ですべて置き換えるので、毎回すべてのフラグを指定してください。たとえば`--reply-to`を省略すると、保存済みの返信先は消えます。保存済みと同じ`--username`を指定してパスワードを指定しなければ、保存済みのパスワードはそのまま残ります。

ワーカーはメールを送るたびに設定を読み込むので、保存した設定は再起動しなくても次のメールから使われます。保存もテストも、そのたびに**監査ログ**に記録されます。

## テナント独自のSMTPアカウント

テナント独自のアカウントは、テナントの管理者がテナント管理画面の**外部連携** › **メール情報**で設定します。**テナントSMTP上書きを有効にする**の**上書きを有効化**をオンにし、プラットフォームのアカウントと同じ項目に加えて「**送信者名（任意）**」を入力します。**接続テスト**を選ぶとフォームの値でテストメッセージが送られ、**保存**を選ぶと保存されます。変更できるのはテナント管理者だけです。手順は[メール](../4-console/3-setup/7-email.md)で説明しています。

保存した次のメールから、そのテナントのメールは、新しい管理者への招待も含めてすべてテナントのアカウントから送られます。上書きをオフにすると、またプラットフォームのアカウントから送られるようになります。

オペレーターが設定することは何もありません。プラットフォーム管理画面からも`publiractl`からも、テナントのアカウントは変更できません。プラットフォームのアカウントのテストは成功するのに、あるテナントのメールが届かなくなったときは、まずそのテナント独自のアカウントを確認してください。

## プレーンテキストとHTML

`email-renderer`を使わなければ、メールはすべてプレーンテキストです。`email-renderer`を使うと、すべてのメールに同じ内容のテキストとHTML版の両方が入り、読者のメールアプリが好みのほうを表示します。有効にするには、`email-renderer`を動かし、`PUBLIRA_EMAIL_RENDERER_URL`で`publira worker`にその場所を指定します。詳しくは[email-rendererでHTMLメールを送る方法](../2-deployments/2-installing.md#email-rendererによるhtmlメール)を参照してください。

有効にすると、`email-renderer`はメール送信に欠かせない部分になります。`email-renderer`が止まっている間、ワーカーはメールをテキストだけで送ることはせず、SMTPサーバーが止まったときと同じ試行回数の範囲で再試行します。そのため、`email-renderer`がそれより長く止まると、メールはやはり失われます。プレーンテキストに戻すには、この環境変数を削除してワーカーを再起動します。

## メールのリンク先

ほとんどのメールには、メールアドレスの確認、パスワードの再設定、招待の承諾などのリンクが入っています。ワーカーは、リクエストがどのホスト名で届いたかを知らないままリンクを組み立てます。そのため、リンクのホスト名とスキームは、`publira worker`が読み込む設定で決まります。

| メール | リンク先 |
| --- | --- |
| 読者あて | テナントのドメイン。たとえば`https://comics.example.com` |
| テナントのスタッフあて | テナントの管理画面のホスト名。別のホスト名を指定していなければ`admin.<domain>` |
| プラットフォームのオペレーターあて | `PUBLIRA_PLATFORM_APP_URL`のアドレス。たとえば`https://platform.example.com` |

テナントのリンクのスキームは`PUBLIRA_TENANT_URL_SCHEME`で決まり、設定しなければ`https`です。`http`にするのは、ブラウザーが実際にHTTPでテナントを開く場合だけにしてください。プラットフォーム管理画面を使う場合は、`publira worker`に必ず`PUBLIRA_PLATFORM_APP_URL`を設定してください。設定しないと、オペレーターあてのリンクがローカルの開発マシンのアドレスになってしまいます。

テナントのリンクはテナントのドメインに合わせて作られます。そのため、テナントを別のホスト名に移すと、それ以降に送るメールのリンクは新しいホスト名になり、それまでに送ったメールのリンクは古いホスト名のままです。詳しくは[テナントを別のホスト名に移す](./2-tenants.md#テナントを別のホスト名に移す)を参照してください。

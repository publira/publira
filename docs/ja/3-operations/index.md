このセクションは、[デプロイ](../2-deployments/index.md)を終えて、すでにサービスを提供しているインストール環境のオペレーターに向けたものです。最初のテナントの後に続く作業を扱います。テナントの追加、各管理画面にログインできる人の管理、プラットフォーム自身のアカウントの整理、そして`publiractl setup`が設定したサービスの変更です。

これらの作業のほとんどは、`publiractl`コマンドラインとプラットフォーム管理画面のどちらからでも行えます。最初のページでその選び方を説明し、以降の各ページでは、両方の方法がある場合は両方を示します。

## このセクションの内容

- [プラットフォーム管理画面とpubliractl](./1-platform-console.md)：2つの選び方、最初のオペレーターの作成、プラットフォーム管理画面にログインするオペレーター。
- [テナント](./2-tenants.md)：テナントの作成、そのドメインと管理画面のホスト、それらの変更、テナントの停止。
- [テナントのスタッフ](./3-tenant-staff.md)：テナントの管理画面にログインする人、そのロール、招待、最後の管理者を失ったテナントの復旧。
- [ユーザー](./4-users.md)：すべてのテナントの読者と、オペレーターがそのアカウントに対してできること。
- [オブジェクトストレージ](./5-object-storage.md)：すべての画像を保持するバケット、その認証情報、画像が`/images`の下でどのように変換、キャッシュ、配信されるか。
- [メール](./6-email.md)：プラットフォームのSMTPアカウントとテナント独自のアカウント、インストール環境が送るメール、HTMLメール、メール内のリンクの行き先。
- [検索](./7-search.md)：ストアフロントの検索エンジン、データベースからOpenSearchまたはElasticsearchへの移行、テキスト解析、インデックスの再構築。
- [Web Push](./8-web-push.md)：ブラウザー通知の有効化と、それに署名する鍵ペア。
- [プラットフォームの既定値とポリシー](./9-platform-policies.md)：すべてのテナントが引き継ぐ既定値、セキュリティとコミュニティの制限、保存期間、そしてそのうちテナントが変更できるもの。
- [定期ジョブとメンテナンスジョブ](./10-scheduled-jobs.md)：`publira worker`が自動で実行するもの、停止の後にどう追いつくか、送信するメール、プッシュ通知、キャッシュの再検証をどう再試行するか、`publiractl job`でジョブを手で実行する方法。
- [モニタリング](./11-monitoring.md)：どのプロセスも応答するヘルスチェックとその確認方法、アラートを設定する価値のあるログの行とメトリクス、OpenTelemetryのメトリクスとトレースの有効化。
- [インストール環境のセキュリティ](./12-security/index.md)：テナントと認証情報を互いに切り離しているもの、各シークレットを置いてよい場所。
  - [シークレットのローテーション](./12-security/1-rotating-secrets.md)：暗号化キー、データベースのパスワード、署名キー、トークンの置き換え。
  - [2段階認証](./12-security/2-two-step-verification.md)：テナントのスタッフとプラットフォームのオペレーターへの要求。
  - [監査ログ](./12-security/3-audit-logs.md)：プラットフォーム管理画面のログとテナントのログが記録するもの、どちらも記録しないもの。

Publiraとは何かをまだ読んでいない場合は、[はじめに](../1-getting-started.md)から読んでください。

インストールを管理する手段は2つあり、ほとんどの作業はどちらでも行えます。このページでは、2つの違いと、プラットフォーム管理画面に最初のオペレーターを作る方法、その後オペレーターを追加してロールを与える方法を説明します。

## どちらを使うか

`publiractl`は、[インストール](../2-deployments/2-installing.md)と同じように、インストールで動かしているリリースのイメージで実行するコマンドです。[Docker Compose](../2-deployments/3-docker-compose.md)で動かしている場合は`docker compose run --rm publiractl`で実行します。`publiractl`は`publira_platform`としてデータベースに直接接続するので、プラットフォーム管理画面を動かしていないインストールでも使えます。必要なのはその接続だけで、アカウントもブラウザーも要らず、ほかのプロセスが動いている必要もありません。

プラットフォーム管理画面は`web-platform`というWebアプリで、オペレーターがログインして使います。専用のアカウントがあり、アカウントごとにロールを持つので、何も変更させずにすべてのテナントを見せるだけ、という使い方ができます。どのオペレーターがどの変更をしたかも記録されます。

どちらも同じコードで書き込むため、どちらで作ったテナントも同じもので、1つのインストールで両方を使えます。違うのは、それぞれで行える作業です。

| 作業 | `publiractl` | プラットフォーム管理画面 |
| --- | --- | --- |
| テナントの作成、変更、停止 | できる | できる |
| テナントのメンバーと管理者の招待 | できる | できる |
| メールを送らずに、パスワード付きの管理画面のアカウントを作る | できる | できない |
| プラットフォームのオペレーター | できない | できる |
| オペレーターがなくした2段階認証の解除 | できる | できない |
| プラットフォームの既定値、ポリシー、保存期間 | できる | できる |
| すべてのテナントの読者 | できない | できる |
| 監査ログの閲覧 | できない | できる |
| メンテナンスジョブの実行 | できる | できない |

テナントやそのスタッフへの変更は、どちらで行ってもすべてプラットフォーム管理画面の**監査ログ**に記録されます。`publiractl`で行った変更にはオペレーターの名前が付かず、実行者は**コマンドライン**になります。

![プラットフォーム管理画面の監査ログのエントリー。テナントを作成した操作で、実行者はコマンドライン、結果は成功で、作成したテナントが表示されている。](./platform-console-audit-log-command-line.png)

プラットフォーム管理画面を動かさなくても、インストールは`publiractl`だけで運用できます。使えなくなるのは監査ログの閲覧と、テナントをまたいだ読者のアカウントの操作です。各テナントの読者は、これまでどおりそのテナントの管理者がテナント管理画面で管理します。

## 最初のオペレーター

[インストール](../2-deployments/2-installing.md#web-platformによるプラットフォーム管理画面)の説明どおりに`web-platform`を起動して開きます。オペレーターが1人もいないうちは、どのアドレスを開いても**初期セットアップ**画面が表示されます。この画面で入力する項目は次のとおりです。

- **氏名**、**メールアドレス**、**パスワード**、**パスワード(確認)**には、最初のオペレーターのアカウントの情報を入力します。
- **既定言語**は、プラットフォーム管理画面が最初に表示に使う言語です。プラットフォームの既定言語にもなり、`publiractl setup`で保存した言語はこれで置き換わります。各オペレーターは、あとから表示言語を切り替えられます。テナントの言語は、テナントを作成するときにそれぞれ選びます。
- **既定タイムゾーン**は、タイムゾーンを指定せずに作成したテナントに最初に設定されるタイムゾーンです。プラットフォーム管理画面も、このタイムゾーンで日時を表示し、日付を数えます。初期値はブラウザーのタイムゾーンで、そのまま保存すると`publiractl setup`で保存したタイムゾーンを置き換えます。別のタイムゾーンにするときは、地域名か都市名で検索して選びます。すでにあるテナントのタイムゾーンは変わりません。
- **既定通貨**は、テナントの管理者が独自の**決済設定**を保存するまで、すべてのテナントが販売に使う通貨です。初期値は`publiractl setup`で保存した通貨なので、そのままにしておけば通貨は変わりません。別の通貨にするときは、通貨名か`EUR`のようなISO 4217のコードを入力して探します。この通貨で販売しているテナントに購入が1件でもあると、そのテナントの価格はこの通貨での金額なので、項目は読み取り専用になり、画面にもその旨が表示されます。保存されている通貨を読み取れない場合も、項目は読み取り専用になってその旨が表示され、セットアップは通貨を変えずに進みます。そのときは、あとで**一般設定**から変更してください。この通貨がどこまで影響するかは[プラットフォームの既定値](./9-platform-policies.md#プラットフォームの既定値)で説明しています。

![初期セットアップ画面。氏名、メールアドレス、パスワード、パスワード(確認)、既定言語、既定タイムゾーン、既定通貨の各項目と、管理ユーザーを作成するボタンがある。](./platform-console-initial-setup.png)

**管理ユーザーを作成する**を選ぶと、**スーパー管理者**のロールを持つアカウントが作成され、ログイン画面に移ります。これ以降、セットアップ画面は表示されません。「最初のオペレーター」を2人作ることはできず、`publiractl`にもオペレーターを作るコマンドはありません。2人目からのオペレーターは、すべてスーパー管理者が**オペレーター管理**で追加します。

プラットフォーム管理画面のアカウントは、プラットフォーム管理画面だけのものです。`publiractl setup`で作成したテナントの管理者はプラットフォーム管理画面にログインできず、オペレーターも自分のアカウントでテナントの管理画面にはログインできません。

## オペレーターのロール

オペレーターには、次の3つのロールのいずれか1つを設定します。

| ロール | できること |
| --- | --- |
| **監査担当** | ダッシュボード、テナントとそのメンバー、ユーザー、監査ログ、プラットフォームの設定など、すべてを閲覧できます。変更できるのは自分のアカウントだけです |
| **オペレーター** | 監査担当ができることに加え、テナント、テナントのメンバーと招待、読者のアカウント、プラットフォームの設定とサービスを変更できます |
| **スーパー管理者** | オペレーターができることに加え、オペレーターを追加し、ロールを変更し、停止や無効化ができます |

監査担当にも、プラットフォーム管理画面はオペレーターと同じ画面とフォームを表示します。ただし、変更を送信すると拒否されます。権限の一覧は[`publira server`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publira/README.md#platform-console-role-permissions)にあります。

## オペレーターの管理

サイドバーの**ガバナンス**にある**オペレーター管理**には、すべてのオペレーターがロールと状態とともに表示されます。ここで変更できるのはスーパー管理者だけです。

![オペレーター管理の一覧とオペレーターを追加ボタン。スーパー管理者、オペレーター、監査担当、停止中のオペレーターが並び、それぞれにメールアドレス、ロール、状態、詳細がある。](./platform-console-operators.png)

### オペレーターを追加する

**オペレーターを追加**でオペレーターの**名前**、**メールアドレス**、**ロール**を入力すると、すぐにアカウントが作成されます。新しいオペレーターには最初のパスワードを設定するリンクがメールで届き、パスワードを設定すればそのパスワードでログインできます。リンクの有効期限は24時間で、期限が切れたときはログイン画面の**パスワードを忘れた場合**から新しいリンクを受け取ります。このメールは、プラットフォーム管理画面が送るほかのメールと同じく、プラットフォームに保存したSMTPの設定を使って`publira worker`が、プラットフォームの既定言語で送ります。

ロールを持たないプラットフォーム管理画面のアカウントがそのメールアドレスですでにある場合は、新しいアカウントを作らずに、そのアカウントにロールを設定します。パスワードは今のまま変わらないので、届くメールにはパスワードを設定するリンクがなく、ログインできるようになったことだけが書かれています。

![オペレーターを追加するフォーム。名前、メールアドレス、ロールの各項目と、追加ボタンがある。](./platform-console-add-operator.png)

すでにオペレーターが使っているメールアドレスは、無効化されたオペレーターのものも含め、追加し直すことはできません。

### オペレーターのロールを変更する

**オペレーター管理**でオペレーターを開き、**ロール変更**で新しいロールを選びます。自分のロールは誰も変更できないので、スーパー管理者が自分を降格させることはなく、操作しているスーパー管理者は必ず残ります。

![オペレーターのページ。上部に停止ボタンと無効化ボタンがある。基本情報にはオペレーターの名前、メールアドレス、現在のロール、状態、アカウントの作成日時が表示され、ロール変更にはロールの項目と保存ボタンがある。](./platform-console-operator.png)

### 停止と無効化

同じ画面で、次の操作ができます。

- **停止**すると、そのオペレーターはログインできなくなり、開いているセッションも終了します。**再有効化**すると、再びログインできるようになります。
- **無効化**すると、アカウントは完全に使えなくなります。無効化したアカウントは二度と使えず、そのメールアドレスを新しいオペレーターとして追加することもできません。そのアカウントで行った変更は、そのアカウントの名前のまま監査ログに残ります。

どちらも、自分のアカウントに対しては行えません。

## オペレーター自身のアカウント

管理画面のヘッダーにあるアカウントメニューの**アカウント設定**では、自分のメールアドレスを変更できます。確認のリンクが今のアドレスと新しいアドレスの両方にメールで届き、両方を開くと変更が反映されます。

![管理画面のヘッダーから開いたアカウントメニュー。オペレーターの名前、公開ID、ロールが表示され、アカウント設定とログアウトがある。](./platform-console-account-menu.png)

![アカウント設定のメールアドレスの変更欄。現在のメールアドレス、新しいメールアドレス、現在のパスワードの各項目と、確認メールを送信するボタンがある。](./platform-console-account-settings.png)

### 2段階認証

同じページの**2段階認証**を有効にすると、ログインのたびに、パスワードに続けて認証アプリのコードを求められるようになります。**設定する**を選ぶと、アプリで読み取るQRコードと、QRコードを読み取れないアプリ向けに同じキーのテキストが表示されます。アプリに表示された6桁のコードを入力し、**2段階認証を有効にする**を選びます。すると10個のリカバリーコードが一度だけ表示されるので、スマートフォンとは別の安全な場所に保管してください。認証アプリが手元にないときは、コードを求められる場面でリカバリーコードを入力すればログインできます。1つのリカバリーコードが使えるのは1回だけです。

![2段階認証が無効のときの、アカウント設定の2段階認証の欄。状態と設定するボタンがある。](./platform-console-account-two-step-verification.png)

有効にすると、ログインはパスワードのあとで**2段階認証**の画面に進み、コードを求められます。リカバリーコードでログインしたときは、残りの数が表示されます。2段階認証が有効なあいだ、同じカードには次の2つのフォームがあります。

- **リカバリーコードを再発行する**と、使用済みかどうかにかかわらず手元のすべてのコードが新しい10個に置き換わります。入力するのは認証アプリのコードで、リカバリーコードは使えません。
- **2段階認証を無効にする**には、認証アプリのコードかリカバリーコードを入力します。あとからいつでも設定し直せ、新しい認証アプリで設定することもできます。

[2段階認証](./12-security/2-two-step-verification.md#プラットフォームのオペレーター)で説明しているとおり、プラットフォームはすべてのオペレーターに2段階認証を必須にできます。必須になると次のログインで設定を求められ、設定を済ませるとログインが完了します。

ログインしたままパスワードを変更するフォームはありません。パスワードを変えるときは、ログアウトしてログイン画面で**パスワードを忘れた場合**を選び、メールで届いたリンクから新しいパスワードを設定します。リンクの有効期限は24時間です。

![プラットフォーム管理画面のログイン画面。メールアドレスとパスワードの項目、ログインボタン、パスワードを忘れた場合のリンクがある。](./platform-console-sign-in.png)

### 2段階認証をなくしたとき

2段階認証を有効にしていたオペレーターが、認証アプリとすべてのリカバリーコードをどちらもなくすと、プラットフォーム管理画面にはログインできません。ほかのオペレーターも、プラットフォーム管理画面からその2段階認証を解除することはできません。この場合は`publiractl`で解除します。

```bash
publiractl operator reset-mfa --email operator@example.com
```

`--email`の代わりに`--user <public ID>`でアカウントを指定することもできます。このコマンドが削除するのはアカウントの認証アプリとすべてのリカバリーコードだけで、パスワード、ロール、状態はそのまま残ります。オペレーターはパスワードだけでログインし、**アカウント設定**から2段階認証を設定し直します。プラットフォームがすべてのオペレーターに2段階認証を必須にしている場合は、ログインが完了する前に設定を求められます。

`publiractl`はアカウントがなくても実行できるので、2段階認証をなくしたのがインストールで唯一の**スーパー管理者**だった場合も、この方法でログインできるようになります。

解除したアカウントはパスワードだけで守られることになり、それはパスワードを盗んだ人が求めてくる状態そのものです。コマンドを実行する前に、依頼がそのオペレーター本人から来たものか確認してください。確認には、依頼が届いた経路ではなく、本人のものだとすでにわかっている連絡手段を使います。

解除の操作は、実行者を**コマンドライン**として、プラットフォーム管理画面の**監査ログ**に記録されます。

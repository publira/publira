Publiraの管理には2つの方法があり、ほとんどの作業はどちらからでも行えます。このページでは、2つの違い、プラットフォーム管理画面で最初のオペレーターを作る方法、そのあとでオペレーターを追加してロールを与える方法を説明します。

## どちらを使うか

`publiractl`は、[インストール](../2-deployments/2-installing.md)と同じく、動かしているリリースのイメージで実行するコマンドです。[Docker Compose](../2-deployments/3-docker-compose.md)の構成では`docker compose run --rm publiractl`で実行します。`publiractl`はデータベースに`publira_platform`として直接接続します。そのため、プラットフォーム管理画面を動かしていなくても使え、データベースへの接続さえあればほかには何も要りません。アカウントもブラウザーも、ほかのプロセスの稼働も不要です。

プラットフォーム管理画面は`web-platform`というWebアプリで、オペレーターがログインして使います。プラットフォーム管理画面には専用のアカウントがあり、アカウントごとにロールを設定します。そのため、何も変更させずに、すべてのテナントを閲覧だけさせることもできます。また、どのオペレーターがどの変更をしたかが記録されます。

どちらも同じコードを通して書き込むので、どちらで作ったテナントにも違いはなく、1つの環境で両方を併用できます。違うのは、それぞれで行える作業です。

| 作業 | `publiractl` | プラットフォーム管理画面 |
| --- | --- | --- |
| テナントの作成、変更、停止 | できる | できる |
| テナントのメンバーと管理者の招待 | できる | できる |
| メールを送らずに、パスワード付きの管理画面のアカウントを作る | できる | できない |
| プラットフォームのオペレーター | できない | できる |
| オペレーターがなくした2段階認証の解除 | できる | できない |
| プラットフォームの既定値、ポリシー、保存期間 | できる | できる |
| すべてのテナントの読者 | できない | できる |
| 監査ログの閲覧 | できない | できる |
| メンテナンスジョブの実行 | できる | できない |

どちらでテナントやスタッフを変更しても、変更はすべてプラットフォーム管理画面の**監査ログ**に記録されます。`publiractl`で行った変更にはオペレーターの名前が付かず、実行者は**コマンドライン**と表示されます。

![プラットフォーム管理画面の監査ログのエントリー。テナントを作成した操作で、実行者はコマンドライン、結果は成功、作成したテナントが表示されている。](./platform-console-audit-log-command-line.png)

プラットフォーム管理画面を動かさなくても、`publiractl`だけでPubliraを運用できます。できなくなるのは、監査ログの閲覧と、テナントをまたいだ読者のアカウントの操作です。各テナントの読者は、引き続きそのテナントの管理者がテナント管理画面から管理できます。

## 最初のオペレーター

[インストール](../2-deployments/2-installing.md#web-platformによるプラットフォーム管理画面)の説明に従って`web-platform`を起動し、ブラウザーで開きます。オペレーターが1人もいないあいだは、どのアドレスを開いても**初期セットアップ**画面が表示され、次の項目の入力を求められます。

- **氏名**、**メールアドレス**、**パスワード**、**パスワード（確認）**。最初のオペレーターのアカウントです。
- **既定言語**。プラットフォーム管理画面の表示に最初に使う言語です。プラットフォームの既定言語にもなり、`publiractl setup`で保存した言語は置き換えられます。表示する言語は各オペレーターがあとで切り替えられます。テナントの言語は、テナントの作成時にそれぞれ選びます。
- **既定タイムゾーン**。タイムゾーンを指定せずに作成したテナントに最初に設定されるタイムゾーンで、プラットフォーム管理画面で日時を表示したり日付を数えたりするときにも使います。初期値はブラウザーのタイムゾーンで、そのままにするとそのタイムゾーンが保存され、`publiractl setup`で保存したものは置き換えられます。別のタイムゾーンにするには、地域名か都市名で検索して選びます。既存のテナントのタイムゾーンは変わりません。
- **既定通貨**。テナントの管理者が独自の**決済設定**を保存するまで、すべてのテナントが販売に使う通貨です。初期値は`publiractl setup`で保存した通貨なので、そのままにすればその通貨のまま変わりません。別の通貨にするには、通貨名か`EUR`のようなISO 4217のコードを入力して探します。この通貨で販売しているテナントで購入が1件でもあると、この項目は読み取り専用になり、画面にもそう表示されます。そのテナントの価格はこの通貨での金額だからです。保存されている通貨を読み取れない場合も、項目は読み取り専用になってその旨が表示され、セットアップでは通貨を変えずにそのまま残します。その場合は、あとで**一般設定**から変更してください。この通貨がどこに影響するかは[プラットフォームの既定値](./9-platform-policies.md#プラットフォームの既定値)で説明しています。

![初期セットアップ画面。氏名、メールアドレス、パスワード、「パスワード（確認）」、既定言語、既定タイムゾーン、既定通貨の各項目と、管理ユーザーを作成するボタン。](./platform-console-initial-setup.png)

**管理ユーザーを作成する**を選ぶと、**スーパー管理者**のロールを持つアカウントが作成され、ログイン画面に移ります。それ以降、セットアップ画面は表示されません。最初のオペレーターをもう1人作ることはできず、`publiractl`にもオペレーターを作る機能はありません。2人目以降のオペレーターは、すべてスーパー管理者が**オペレーター管理**から追加します。

プラットフォーム管理画面のアカウントは、プラットフォーム管理画面専用です。`publiractl setup`で作成したテナントの管理者は、プラットフォーム管理画面にログインできません。オペレーターも、オペレーターのアカウントでテナントの管理画面にはログインできません。

## オペレーターのロール

オペレーターには、次の3つのロールのいずれかを設定します。

| ロール | できること |
| --- | --- |
| **監査担当** | すべてを閲覧できます。対象はダッシュボード、テナントとそのメンバー、ユーザー、監査ログ、プラットフォームの設定です。変更できるのは自分のアカウントだけです |
| **オペレーター** | 監査担当ができることに加えて、テナント、テナントのメンバーと招待、読者のアカウント、プラットフォームの設定とサービスを変更できます |
| **スーパー管理者** | オペレーターができることに加えて、オペレーターの追加、ロールの変更、停止と無効化ができます |

プラットフォーム管理画面は、監査担当にもオペレーターと同じ画面とフォームを表示しますが、変更を送信すると拒否します。権限の一覧は[`publira server`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publira/README.md#platform-console-role-permissions)にあります。

## オペレーターの管理

サイドバーの**ガバナンス**にある**オペレーター管理**には、すべてのオペレーターがロールと状態とともに一覧表示されます。ここで変更を行えるのはスーパー管理者だけです。

![オペレーター管理の一覧とオペレーターを追加ボタン。スーパー管理者、オペレーター、監査担当、停止中のオペレーターが、それぞれメールアドレス、ロール、状態、詳細とともに並んでいる。](./platform-console-operators.png)

### オペレーターを追加する

**オペレーターを追加**で、オペレーターの**名前**、**メールアドレス**、**ロール**を入力すると、その場でアカウントが作成されます。新しいオペレーターには最初のパスワードを設定するためのリンクがメールで届き、パスワードを設定するとそのパスワードでログインできます。リンクの有効期限は24時間です。期限が切れた場合は、ログイン画面で**パスワードを忘れた場合**を選ぶと新しいリンクを受け取れます。このメールは、プラットフォーム管理画面が送るほかのメールと同じく、プラットフォームに保存したSMTPの設定を使って`publira worker`が送ります。言語はプラットフォームの既定言語です。

そのメールアドレスで、ロールを持たないプラットフォーム管理画面のアカウントがすでにある場合は、新しいアカウントは作られず、既存のアカウントにロールが設定されます。そのアカウントのパスワードは変わらないので、メールにはパスワード設定のリンクが含まれず、ログインできるようになったことだけが書かれています。

![オペレーターを追加するフォーム。名前、メールアドレス、ロールの各項目と、追加ボタン。](./platform-console-add-operator.png)

すでにオペレーターが使っているメールアドレスは、無効化されたオペレーターのものも含めて、もう一度追加することはできません。

### オペレーターのロールを変更する

**オペレーター管理**でオペレーターを開き、**ロール変更**で新しいロールを選びます。自分のロールは誰も変更できません。そのため、スーパー管理者が自分を降格することはなく、操作しているスーパー管理者が必ず残ります。

![オペレーターの詳細ページ。上部に停止と無効化のボタン、基本情報にオペレーターの名前、メールアドレス、現在のロール、状態、アカウントの作成日時、ロール変更にロールの項目と保存ボタンがある。](./platform-console-operator.png)

### 停止と無効化

同じ画面で次の操作ができます。

- **停止**すると、そのオペレーターはログインできなくなり、開いているセッションも終了します。**再有効化**すると、再びログインできるようになります。
- **無効化**すると、アカウントは完全に使えなくなります。無効化したアカウントは二度と使えず、そのメールアドレスを新しいオペレーターとして追加することもできません。そのアカウントで行った変更は、そのアカウントの名前で監査ログに残ります。

どちらの操作も、自分のアカウントには行えません。

## オペレーター自身のアカウント

管理画面のヘッダーにあるアカウントメニューの**アカウント設定**で、自分のメールアドレスを変更できます。現在のアドレスと新しいアドレスの両方に確認のリンクがメールで届き、両方のリンクを開くと変更が反映されます。

![管理画面のヘッダーから開いたアカウントメニュー。オペレーターの名前、公開ID、ロールと、アカウント設定、ログアウト。](./platform-console-account-menu.png)

![アカウント設定のメールアドレスの変更欄。現在のメールアドレス、新しいメールアドレス、現在のパスワードの各項目と、確認メールを送信するボタン。](./platform-console-account-settings.png)

### 2段階認証

同じページの**2段階認証**を有効にすると、ログインのたびに、パスワードのあとで認証アプリのコードの入力を求められます。**設定する**を選ぶと、アプリで読み取るQRコードと、QRコードを読み取れないアプリのために同じキーのテキストが表示されます。アプリに表示される6桁のコードを入力して、**2段階認証を有効にする**を選びます。続いて、10個のリカバリーコードが一度だけ表示されます。スマートフォンとは別の安全な場所に保管してください。認証アプリが手元にないときは、ログインでコードを求められる場面ならどこでも、リカバリーコードでログインできます。1つのコードが使えるのは1回だけです。

![2段階認証が無効のときのアカウント設定の2段階認証の欄。状態と設定するボタン。](./platform-console-account-two-step-verification.png)

有効にしたあとは、ログインのときにパスワードの次に**2段階認証**の画面が表示され、コードを求められます。リカバリーコードでログインすると、残りの数が表示されます。2段階認証が有効なあいだ、同じカードには次の2つのフォームがあります。

- **リカバリーコードを再発行する**と、使用済みかどうかにかかわらず手元のすべてのコードが、新しい10個のコードに置き換わります。入力するのは認証アプリのコードで、リカバリーコードは使えません。
- **2段階認証を無効にする**には、認証アプリのコードかリカバリーコードを入力します。無効にしたあとも、いつでも設定し直せます。新しい認証アプリがあれば、それを使って設定できます。

[2段階認証](./12-security/2-two-step-verification.md#プラットフォームのオペレーター)のページで説明しているとおり、プラットフォームの設定で、すべてのオペレーターに2段階認証を必須にできます。必須にすると、次のログイン時に設定を求められ、設定を済ませるとログインが完了します。

ログインしたままパスワードを変更するフォームはありません。ログアウトしてからログイン画面で**パスワードを忘れた場合**を選び、メールで届いたリンクから新しいパスワードを設定します。リンクの有効期限は24時間です。

![プラットフォーム管理画面のログイン画面。メールアドレス、パスワードの各項目、ログインボタン、パスワードを忘れた場合のリンク。](./platform-console-sign-in.png)

### 2段階認証をなくしたとき

2段階認証を有効にしたオペレーターが、認証アプリとすべてのリカバリーコードを両方なくすと、プラットフォーム管理画面にログインできなくなります。ほかのオペレーターが、プラットフォーム管理画面からそのアカウントの2段階認証を解除することもできません。この場合は`publiractl`で解除します。

```bash
publiractl operator reset-mfa --email operator@example.com
```

`--email`の代わりに`--user <public ID>`でアカウントを指定することもできます。このコマンドはアカウントの認証アプリとすべてのリカバリーコードを削除するだけで、パスワード、ロール、状態は変わりません。オペレーターはそのあとパスワードだけでログインし、**アカウント設定**から2段階認証を設定し直します。プラットフォームがすべてのオペレーターに2段階認証を必須にしている場合は、ログインが完了する前に設定を求められます。

`publiractl`の実行にはアカウントが要らないので、2段階認証をなくしたオペレーターが唯一の**スーパー管理者**だった場合も、この方法でログインできる状態に戻せます。

解除すると、アカウントはパスワードだけで守られる状態になります。これは、盗んだパスワードを持つ人が求めてくる状態そのものです。コマンドを実行する前に、依頼が本当にそのオペレーター本人から来たものかを確認してください。確認には、依頼が届いた経路ではなく、本人のものだとすでにわかっている連絡手段を使います。

解除の操作は、プラットフォーム管理画面の**監査ログ**に、実行者を**コマンドライン**として記録されます。

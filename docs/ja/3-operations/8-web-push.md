読者は、テナントのサイトが自分のブラウザーに通知を送ることを許可できます。許可しておけば、サイトを開かなくても新しいエピソードの公開を知ることができます。インストールは各読者のブラウザーのプッシュサービスを通して通知を送り、1件ずつにインストール自身が持つVAPIDの鍵ペアで署名します。Web Pushは任意の機能で、有効にするまではオフです。一度も有効にしないインストールではブラウザー通知が送られないだけで、何かが失敗することはありません。

このページの`publiractl`コマンドは、コマンドの部分だけを示しています。[プラットフォーム管理画面とpubliractl](./1-platform-console.md#どちらを使うか)の説明に従い、`PUBLIRA_PLATFORM_DB_URL`に`publira_platform`の接続先を設定して実行してください。`PUBLIRA_SECRET_ENCRYPTION_KEYS`と`PUBLIRA_SECRET_ENCRYPTION_PRIMARY_KEY_ID`には、各プロセスと同じ値を設定します。フラグの一覧は[`publiractl`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#webpush)にあります。

## 有効にするのに必要なもの

必要なものは、VAPIDの鍵ペアとサブジェクトの2つです。どちらも、プロセスの環境変数ではなくインストールの設定に保存されます。

### VAPIDの鍵ペア

ブラウザーのプッシュサービスは、届いた通知を1件ずつこの鍵ペアで検証します。鍵ペアはPubliraが生成するので、どちらの鍵も運用者が扱うことはありません。秘密鍵はインストールの暗号化キーで暗号化して保存され、表示されることはありません。公開鍵は、読者のブラウザーが通知を購読するときにそのブラウザーへ渡されます。

### サブジェクト

インストールが送る通知に問題があったときに、プッシュサービスが運用者に連絡するための連絡先です。`mailto:push@example.com`の形のメールアドレスか、問い合わせページの`https://`のURLを指定します。

サブジェクトを保存するまで、Web Pushはオフのままです。オフのあいだ、ストアフロントはブラウザー通知を案内せず、ワーカーも通知を送りません。

## 有効にする

### publiractlから

```bash
publiractl webpush init --subject mailto:push@example.com
publiractl webpush show
```

`webpush init`は、鍵ペアがまだ保存されていなければ生成し、サブジェクトを保存します。`webpush show`は、サブジェクトと公開鍵を表示します。

`publiractl setup`でもこの手順を尋ねられるので、そこで答えたインストールでは、Web Pushはすでに有効です。

### プラットフォーム管理画面から

サイドバーの**外部サービス**にある**Web Push**を選びます。鍵ペアがまだ保存されていなければ、画面を開いたときに生成されます。**連絡先(VAPID subject)**を入力して**Web Push設定を保存**を選ぶと、Web Pushが設定済みであることが画面に表示されます。保存できるのはオペレーターとスーパー管理者で、監査担当は画面を閲覧できるだけです。

![Web Pushを設定済みのブラウザー通知の画面。連絡先(VAPID subject)の入力欄とWeb Push設定を保存ボタンがある。](./web-push-settings.png)

APIサーバーにシークレットの暗号化キーがないためWeb Pushを設定できない、と画面に表示されたときは、`publira server`が`PUBLIRA_SECRET_ENCRYPTION_KEYS`なしで起動されています。ほかのプロセスと同じキーを設定して`publira server`を再起動し、画面を開き直してください。

### 動作を確認する

APIとワーカーは10秒ごとに設定を読み直すので、保存したサブジェクトは再起動しなくても届きます。最初に保存したときは、APIがサブジェクトを返すようになる約20秒後に、ワーカーが全テナントのサイト情報のキャッシュを破棄します。各サイトは、その次のリクエストからブラウザー通知を案内するようになります。このキャッシュの破棄はアウトボックスから送るキャッシュの再検証の1つで、ほかの再検証と同じように送られるので、[アウトボックス](./10-scheduled-jobs.md#アウトボックスメールプッシュ通知キャッシュの再検証)で説明するとおり、`PUBLIRA_REVALIDATE_TOKEN`のないワーカーには送れません。

実際に動くか確かめるには、テナントのサイトに読者としてログインし、読者の通知設定の**ブラウザ通知**で**このブラウザでプッシュ通知を受け取る**をオンにします。通知設定の**ブラウザ**の列はオンのままにして、シリーズを1つフォローしてください。そのシリーズで次のエピソードが公開されてサイトに表示されると、ブラウザー通知が届きます。

保存は、そのたびに**監査ログ**に記録されます。

## あとから変更する

サブジェクトは、`webpush init`に新しい`--subject`を指定するか同じ画面から、いつでも変更できます。削除はできず、一度サブジェクトを保存すると、Web Pushは有効なままです。

鍵ペアが置き換わることはありません。ブラウザーの購読はどれもこの公開鍵に対して登録されているので、鍵ペアを新しくすると、通知を有効にしたすべての読者への通知が、何の知らせもなく止まってしまうからです。`publiractl`にもプラットフォーム管理画面にも、2つ目の鍵ペアを生成する機能はありません。このため、鍵ペアはインストールのバックアップで必ず残すものの1つです。鍵ペアは暗号化キーで暗号化されてデータベースに入っているので、データベースと暗号化キーのどちらかを失えば、鍵ペアも失われます。暗号化キーをローテーションしても、鍵ペアはそのまま使えます。[シークレットの暗号化キーのローテーション](./12-security/1-rotating-secrets.md#シークレットの暗号化キーのローテーション)で説明するとおり、`publiractl db reseal`がほかのデータと一緒に秘密鍵を新しいキーで暗号化し直すからです。

読者が通知の許可を取り消したり、サイトのデータを消去したりすると、ブラウザーはその購読を手放します。手放された購読は、次にそこへの通知が拒否されたときに削除されます。

## モバイルアプリの通知

Web Pushが対象にするのはブラウザーだけです。テナントのモバイルアプリに届く通知はテナント独自のFirebaseプロジェクトを通して送られ、その設定はテナントの管理者がテナント管理画面で行います。インストールの設定には何も含まれません。設定方法は[プッシュ通知](../5-mobile-app/3-push-notifications.md)で説明しています。

読者は、テナントのサイトが自分のブラウザーに通知を送ることを許可できます。これにより、サイトを開かなくても新しいエピソードを知ることができます。インストール環境は各読者のブラウザーのプッシュサービスを通して通知を送り、インストール環境が持つVAPIDの鍵ペアで1件ずつ署名します。Web Pushは任意で、有効にするまではオフです。一度も有効にしないインストール環境はブラウザー通知を送りませんが、それによって何かが失敗することはありません。

このページの`publiractl`コマンドは、コマンド単体で示しています。[プラットフォーム管理画面とpubliractl](./1-platform-console.md#どちらを使うか)の説明どおりに、`PUBLIRA_PLATFORM_DB_URL`に`publira_platform`の接続先を設定し、各プロセスと同じ`PUBLIRA_SECRET_ENCRYPTION_KEYS`と`PUBLIRA_SECRET_ENCRYPTION_PRIMARY_KEY_ID`を指定して実行してください。すべてのフラグは[`publiractl`リファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#webpush)にあります。

## 有効にするのに必要なもの

必要なものは2つで、どちらもプロセスの環境ではなく、インストール環境の設定に保存されます。

- **VAPIDの鍵ペア**：ブラウザーのプッシュサービスが、すべての通知をこれに照らして確認します。鍵ペアはPubliraが生成するので、どちらの鍵も自分で扱うことはありません。秘密鍵はインストール環境の暗号鍵で暗号化して保存され、表示されることはありません。公開鍵は、各読者のブラウザーが購読するときにブラウザーに渡されます。
- **サブジェクト**：インストール環境が送るものに問題があった場合に、プッシュサービスが連絡できる連絡先です。`mailto:push@example.com`の形のメールアドレスか、問い合わせページの`https://`のURLを指定します。

サブジェクトが保存されるまで、Web Pushはオフのままです。それまでストアフロントはブラウザー通知を提供せず、ワーカーも通知を送りません。

## 有効にする

### publiractlから

```bash
publiractl webpush init --subject mailto:push@example.com
publiractl webpush show
```

`webpush init`は、鍵ペアがまだ保存されていなければ生成し、サブジェクトを保存します。`webpush show`はサブジェクトと公開鍵を表示します。

`publiractl setup`でもこの手順を案内しているので、そこで回答したインストール環境では、Web Pushはすでに有効になっています。

### プラットフォーム管理画面から

サイドバーの**外部サービス**の下にある**Web Push**を選びます。鍵ペアがまだ保存されていなければ、画面を開いたときに生成されます。「**連絡先（VAPID subject）**」を入力して**Web Push設定を保存**を選ぶと、画面にWeb Pushが設定済みであることが表示されます。保存できるのはオペレーターまたはスーパー管理者で、監査担当は画面を閲覧することしかできません。

![Web Pushが設定済みのブラウザー通知の画面。連絡先（VAPID subject）とWeb Push設定を保存。](./web-push-settings.png)

APIサーバーにシークレットの暗号鍵がないためWeb Pushを設定できない、と画面に表示された場合は、`publira server`が`PUBLIRA_SECRET_ENCRYPTION_KEYS`なしで起動されています。ほかのプロセスと同じ鍵を設定して再起動し、画面を開き直してください。

### 動作を確認する

APIとワーカーは10秒ごとに設定を読み直すので、保存したサブジェクトは再起動なしで反映されます。また、最初の保存から約20秒後、APIがサブジェクトを含めて応答するようになった時点で、ワーカーは各テナントのサイト情報のキャッシュをすべて破棄します。これにより、各サイトは次のリクエストからブラウザー通知を提供します。この破棄はアウトボックスのキャッシュ再検証であり、ほかの再検証と同じように送られます。[アウトボックス](./10-scheduled-jobs.md#アウトボックスメールプッシュ通知キャッシュの再検証)で説明するとおり、`PUBLIRA_REVALIDATE_TOKEN`のないワーカーはこれを送れません。

動作を確認するには、テナントのサイトに読者としてログインし、読者の通知設定の**ブラウザ通知**で**このブラウザでプッシュ通知を受け取る**をオンにし、通知設定の**ブラウザ**の列をオンのままにして、シリーズをフォローします。そのシリーズで次に公開され、サイトに表示されたエピソードが、ブラウザー通知として届きます。

保存はそれぞれ**監査ログ**に記録されます。

## あとから変更する

サブジェクトは、`webpush init`に新しい`--subject`を指定するか、同じ画面から、いつでも変更できます。削除することはできません。一度サブジェクトを保存すると、Web Pushは有効なままになります。

鍵ペアが置き換えられることはありません。ブラウザーの購読はすべてその公開鍵に対して行われているので、新しい鍵ペアにすると、通知を有効にしたすべての読者への通知が知らないうちに止まってしまいます。`publiractl`にもプラットフォーム管理画面にも、2つ目の鍵ペアを生成する機能はありません。そのため、鍵ペアはインストール環境のバックアップで保持すべきものの一部になります。鍵ペアはデータベースに暗号鍵で暗号化して保存されており、データベースと暗号鍵のどちらかを失うと失われます。暗号鍵をローテーションしても鍵ペアは保たれます。[シークレットの暗号鍵をローテーションする](./12-security/1-rotating-secrets.md#シークレット暗号化キーの入れ替え)で説明するとおり、`publiractl db reseal`がほかのすべてのものと一緒に秘密鍵を新しい鍵で暗号化し直します。

ブラウザーが手放した購読（読者が許可を取り消したり、サイトのデータを消去したりした場合）は、次にその購読への通知が拒否されたときに削除されます。

## モバイルアプリの通知

Web Pushが対象とするのはブラウザーだけです。テナントのモバイルアプリが受け取る通知は、そのテナント独自のFirebaseプロジェクトを通して送られ、テナントの管理者がテナント管理画面から設定します。そのどれもインストール環境の設定ではありません。その設定については[プッシュ通知](../5-mobile-app/3-push-notifications.md)で説明します。

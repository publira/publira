Publiraには、互いにエントリーを共有しない2つの監査ログがあります。オペレーターと`publiractl`による変更を記録するプラットフォーム管理画面のログと、スタッフがテナント管理画面で行った変更を記録する各テナントのログです。エントリーは削除されず、Publiraのプロセスが接続するどのロールにも、データベースはエントリーの変更を許しません。例外はデータベース自身が行う変更だけで、操作したアカウントが削除されると、エントリーにはアカウントの代わりにその名前と公開IDが残ります。どちらのログも、期間を指定して[CSVでエクスポート](#ログのエクスポート)できます。

## プラットフォーム管理画面のログ

プラットフォーム管理画面の**ガバナンス**にある**監査ログ**には、エントリーが新しい順に1ページ20件ずつ表示されます。**監査担当**を含め、すべてのオペレーターが閲覧できます。各エントリーには**時刻**、ロール付きの**実行者**、操作とその結果、**対象**が表示されます。`publiractl`で行った変更にはオペレーターが記録されず、実行者は**コマンドライン**になります。

一覧は、**開始日**と**終了日**で指定した期間、公開IDで指定した1人の実行者、1種類の操作で絞り込めます。期間はプラットフォームの**既定タイムゾーン**での日単位です。テナントのページで**監査ログを確認**を選ぶと、そのテナントでも絞り込んだ一覧が開きます。表示されるのは、そのテナントや、テナントへの招待、テナントのスタッフと読者のアカウントを変更したエントリーです。一覧の上にはテナント名が表示され、その閉じるボタンでテナントの絞り込みだけを外せます。**クリア**を選ぶと、すべての絞り込みが外れます。

![1つのテナントで絞り込んだプラットフォーム管理画面の監査ログ。閉じるボタン付きのテナント「Platform Docs Tenant」、開始日と終了日、実行者と操作の絞り込み、「絞り込む」と「クリア」、その横に「CSVをダウンロード」があります。6件のエントリーには、それぞれ時刻、実行者とそのロールまたは「コマンドライン」、操作と結果、対象が表示されています。](./audit-logs-tenant-filter.png)

記録される操作は次のとおりです。

| 対象 | 記録される操作 |
| --- | --- |
| オペレーター | 追加、変更、停止、再有効化、無効化。各オペレーター自身の2段階認証については、設定、ログイン時のコードの入力(正誤を問わない)、リカバリーコードでのログイン、リカバリーコードの再発行、無効化 |
| プラットフォームの設定とサービス | 一般設定、セキュリティとコミュニティのポリシー、保持期間の既定値、メールとストレージと検索の設定、Web Pushの連絡先の保存。メール、ストレージ、検索の接続テストとその結果 |
| テナントとそのスタッフ | テナントの作成、変更、停止、再開。管理者の招待と、招待の再送やキャンセル。メンバーの追加、パスワードを指定したメンバーの作成、ロールの変更、メンバーの削除 |
| 読者 | オペレーターによるアカウントの停止、復元、削除 |
| ログ自体 | エクスポート。対象期間と、絞り込んだテナントも記録します |

## テナントのログ

テナント管理画面の**管理**にある**監査ログ**には、スタッフがその管理画面で行った操作が、2段階認証も含めて記録されます。閲覧できるのはそのテナントのテナント管理者だけです。記録される内容は[監査ログ](../../4-console/3-setup/8-audit-log.md)を参照してください。

テナントのログは、プラットフォーム管理画面からは閲覧できません。オペレーターがプラットフォーム管理画面や`publiractl`でテナントに対して行った変更は、テナントのログではなく、プラットフォーム管理画面のログに記録されます。

## ログのエクスポート

どちらのログも、閲覧できる人なら最長366日分を1つのCSVファイルとしてエクスポートできます。テナントのログはそのテナントのテナント管理者が、プラットフォーム管理画面のログは**監査担当**を含むすべてのオペレーターがエクスポートできます。期間は日単位で、テナントのログはテナントのタイムゾーン、プラットフォーム管理画面のログはプラットフォームの**既定タイムゾーン**で区切ります。実行者と操作の絞り込みは、一覧と同じくファイルにも適用されます。プラットフォーム管理画面のログでは、テナントの絞り込みも適用されます。

ファイルには、期間内のすべてのエントリーが古い順に1行ずつ入ります。各行に入るのは次の値です。

- 記録された時刻(期間のタイムゾーンのオフセット付き)
- 実行者の公開ID、名前、ロール
- 操作とその結果と理由
- 操作の対象の種類とID
- クライアントのアドレス

プラットフォーム管理画面のログでは、これに加えて、各エントリーのテナントの公開IDと名前、操作の対象の公開IDと名前も入ります。ファイルはバイトオーダーマーク付きのUTF-8です。バイトオーダーマークがあるので、表計算ソフトはファイルをUTF-8として読み込みます。表計算ソフトが数式とみなす値には、テキストのまま扱われるよう先頭にアポストロフィを付けています。

エクスポートも、エクスポートしたログにエントリーとして記録されます。誰がどの期間のコピーをいつ取ったかは、ログを見ればわかります。

プラットフォーム管理画面では、**監査ログ**の絞り込みの横にある**CSVをダウンロード**を選ぶと、表示中の期間、テナント、実行者、操作に当てはまるエントリーを保存できます。ファイル名は`platform-audit-log-2026-04-01--2026-04-30.csv`のように期間を表します。**終了日**を指定しなければ、期間は今日までです。**開始日**を指定しなければ、**終了日**(指定がなければ今日)までの366日間になります。それより長い期間や、**開始日**が**終了日**より後になっている期間は、絞り込み直すまでダウンロードできません。ダウンロードするたびに、ログには**監査ログをCSVでダウンロード**と記録されます。

## どちらのログにも記録されないもの

### パスワードによるログイン

ログインの成功もパスワードの誤りも、エントリーには残りません。テナントのログに記録されるのは、そのあとの2段階認証の段階だけです。`publira server`は、サイト、テナント管理画面、プラットフォーム管理画面へのログインの試行をすべて、`audit auth`で始まる行としてログに出力します。行には操作、結果、理由、クライアントのアドレスが含まれ、たとえば`audit auth action=admin_login outcome=failure ... reason=invalid_credentials`のようになります。ログインの記録が必要なら、サーバーのログを保管してください。

### Publiraのシークレットと環境変数

キー、パスワード、トークンのローテーションはPubliraの外で行うので、どこにもエントリーは残りません。いつ何をローテーションしたかは、別に記録しておいてください。

### 一覧から失われるエントリー

すべてのエントリーは、保存される前に`msg=audit`を含む行として`publira server`のログにも出力されます。ほとんどのエントリーは、サーバーのメモリー上のキューを経由して、変更の少しあとに保存されます。何回か試みても保存できなかったエントリーや、サーバーの停止時にまだキューに残っていたエントリーは管理画面の一覧からは失われますが、このログの行には残ります。こうした欠落を検知するアラートに使うログとメトリクスは、[監視](../11-monitoring.md#監査ログ)を参照してください。

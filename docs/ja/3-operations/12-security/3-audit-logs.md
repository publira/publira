インストール環境は、エントリーを決して共有しない2つの監査ログを保持します。オペレーターと`publiractl`が変更したものを記録するプラットフォーム管理画面のログと、スタッフがテナント管理画面で変更したものを記録する各テナントのログです。エントリーは決して削除されず、データベースは、Publiraのプロセスが接続するどのロールにも、エントリーの変更を一切許しません。唯一の例外はデータベース自身が行う変更で、操作したアカウントが削除されたとき、エントリーはそのアカウントの代わりに、その名前と公開IDを保持します。どちらのログも、期間を区切って[CSVとしてエクスポート](#ログのエクスポート)できます。

## プラットフォーム管理画面のログ

プラットフォーム管理画面の**ガバナンス**の下にある**監査ログ**は、新しいエントリーから順に、1ページに20件ずつ一覧表示します。**監査担当**を含め、すべてのオペレーターが読めます。各エントリーには、**時刻**、ロール付きの**実行者**、結果付きの操作、そして**対象**が表示されます。`publiractl`から行った変更はどのオペレーターも示さず、その実行者は**コマンドライン**です。一覧は、**開始日**と**終了日**による期間（プラットフォームの**既定タイムゾーン**での丸1日単位）、公開IDによる1人の実行者、1種類の操作で絞り込めます。テナントのページの**監査ログを確認**を使うと、そのテナントでも絞り込んだ状態で一覧が開きます。そのテナント、その招待、そのスタッフと読者のアカウントを変更したエントリーです。一覧の上にはそのテナントの名前が表示され、その閉じるボタンはその絞り込みだけを外します。**クリア**はすべての絞り込みを外します。

![1つのテナントで絞り込んだプラットフォーム管理画面の監査ログ。閉じるボタン付きの「テナント: Platform Docs Tenant」、開始日と終了日、実行者と操作の絞り込み、「絞り込む」と「クリア」、その横の「CSVをダウンロード」、そして6件のエントリーがあり、各エントリーには時刻、実行者とそのロールまたは「コマンドライン」、操作とその結果、対象が表示されている。](./audit-logs-tenant-filter.png)

記録するもの：

- **オペレーター**：追加、変更、停止、再有効化、無効化。そして各オペレーター自身の2段階認証：設定、ログイン時に求められたコード（正しかったか誤っていたか）、リカバリーコードによるログイン、新しいリカバリーコード、無効化。
- **プラットフォームの設定とサービス**：一般設定、セキュリティとコミュニティのポリシー、保持期間の既定値、メール、ストレージ、検索の設定、Web Pushの連絡先の各保存と、メール、ストレージ、検索の接続の各テストとその結果。
- **テナントとそのスタッフ**：テナントの作成、変更、停止、再開。管理者の招待と、招待の再送とキャンセル。メンバーの追加、パスワード付きでの作成、新しいロールの付与、削除。
- **読者**：オペレーターによるアカウントの停止、復元、削除。
- **ログ自体**：ログの各エクスポートと、それが対象とした期間、絞り込んだテナント。

## テナントのログ

各テナントの管理画面の**管理**の下にある**監査ログ**は、スタッフがそこで行うことを2段階認証も含めて記録し、読めるのはそのテナントのテナント管理者だけです。何を記録するかは[監査ログ](../../4-console/3-setup/8-audit-log.md)にあります。プラットフォーム管理画面からは読めず、あなたがプラットフォーム管理画面や`publiractl`からテナントに対して変更したものは、テナントのログではなく、プラットフォーム管理画面のログに記録されます。

## ログのエクスポート

どちらのログも、それを読める人が、最長366日を対象とする1つのCSVファイルとしてエクスポートできます。テナントのログはそのテナント管理者が、プラットフォーム管理画面のログは**監査担当**を含むすべてのオペレーターがエクスポートできます。期間は丸1日単位で、テナントのログではテナントのタイムゾーン、プラットフォーム管理画面のログではプラットフォームの**既定タイムゾーン**で数えます。実行者、操作、そしてプラットフォーム管理画面のログではテナントが、一覧を絞り込むのと同じようにファイルを絞り込みます。

ファイルには、その期間のすべてのエントリーが古い順に、1エントリー1行で入ります。記録された時刻（期間のタイムゾーンのオフセット付き）、実行者の公開ID、名前、ロール、操作、その結果、その理由、操作の対象の種類とID、そしてクライアントのアドレスです。プラットフォーム管理画面のログのファイルには、各エントリーのテナントの公開IDと名前、そしてエントリーが操作した対象の公開IDと名前も入ります。ファイルはバイトオーダーマーク付きのUTF-8で、これによって表計算ソフトがUTF-8として読み込みます。また、表計算ソフトが数式として読むような値は、テキストのままになるように先頭にアポストロフィを付けて書かれます。

エクスポート自体も、それが読んだログのエントリーになるので、誰がどの期間のコピーをいつ取ったかがログに残ります。

プラットフォーム管理画面では、**監査ログ**の絞り込みの横にある**CSVをダウンロード**で、表示している期間、テナント、実行者、操作のエントリーを、`platform-audit-log-2026-04-01--2026-04-30.csv`のように期間にちなんだ名前のファイルとして保存します。**終了日**がなければ期間は今日で終わり、**開始日**がなければ、期間は**終了日**または今日で終わる366日間です。それより長い期間や、**開始日**が**終了日**より後の期間は、絞り込むまでダウンロードできません。各ダウンロードは、ログに**監査ログをCSVでダウンロード**として表示されます。

## どちらのログも記録しないもの

- **パスワードによるログイン。** ログインの成功も誤ったパスワードもエントリーを残しません。テナントのログが記録するのは、そのあとに続く2段階認証の手順だけです。`publira server`は、サイト、テナント管理画面、プラットフォーム管理画面へのすべてのログインの試行を、`audit auth action=admin_login outcome=failure ... reason=invalid_credentials`のように、操作、結果、理由、クライアントのアドレスを伴う`audit auth`で始まる行としてログに書きます。その記録が必要なら、サーバーのログを保管してください。
- **インストール環境のシークレットと変数。** キー、パスワード、トークンの入れ替えはPubliraの外で行われるので、どこにもエントリーを残しません。いつ何を入れ替えたかは、自分で記録しておいてください。

すべてのエントリーは、保存される前に、`msg=audit`を伴う行として`publira server`のログにも書かれます。ほとんどのエントリーは、サーバーのメモリー上のキューから、変更の少しあとに保存されます。何度か試みても保存できなかったエントリーや、サーバーが止まったときにまだキューにあったエントリーは、管理画面の一覧からは失われますが、そのログ行には残ります。そのような欠落に対してアラートを出すべきログ行とメトリクスは、[モニタリング](../11-monitoring.md#監査ログ)にあります。

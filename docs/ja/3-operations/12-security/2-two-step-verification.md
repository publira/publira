このページはオペレーター向けです。テナントのスタッフとプラットフォーム管理画面のオペレーターが2つ目の認証要素でアカウントを守る方法、それを必須にする方法、認証要素を失ったときの対処を説明します。

## テナントのスタッフ

テナントのスタッフは、管理画面の**アカウント設定**から、認証アプリと10個のリカバリーコードで自分のアカウントを守れます。スタッフ向けの手順は[自分のアカウント](../../4-console/3-setup/9-your-account.md)で説明しています。

スタッフは、パスキーやセキュリティキーで2段階認証を行うこともできます。[パスキーでのログイン](../../4-console/3-setup/9-your-account.md#パスキーでのログイン)を参照してください。後述の必須設定に対して、パスキーは認証アプリと同じように扱われます。ログイン時に2段階認証の設定を求められたテナント管理者は、認証アプリの代わりにパスキーを登録できます。1つのアカウントのパスキーと認証アプリは同じ10個のリカバリーコードを共有し、パスキーが拒否された回数は、コードを間違えた回数と同じロックの判定に数えられます。

パスキーは管理画面のホストに結び付きます。管理画面がどこで提供されていても同じで、管理画面が`admin.<domain>`のようにテナントのドメインの下にある場合でも、テナントのドメインには結び付きません。そのため、新しい管理画面用のドメインを設定したり、管理画面が`admin.<domain>`にあるテナントのドメインを変更したりして[管理画面を別のホストに移す](../2-tenants.md#テナントを別のホスト名に移す)と、スタッフが登録したパスキーはすべて使えなくなります。認証アプリやリカバリーコードを持っているスタッフは、それを使ってログインします。2つ目の認証要素がパスキーだけだったスタッフは、必須設定がそのロールを対象にしていれば2段階認証の設定をやり直すよう求められ、対象外であればパスワードだけでログインします。管理画面を元のホストに戻せば、古いパスキーは再び使えるようになります。

Publiraのすべてのテナント管理者に、2段階認証を必須にできます。プラットフォーム管理画面の**ポリシー**にある**セキュリティ**で、**テナント管理者に多要素認証を必須にする**にチェックを入れて**セキュリティポリシーを保存**を選ぶか、次のコマンドを実行します。

```bash
publiractl policy set --mfa-required-for-tenant-admin
```

![セキュリティポリシーのページの末尾。「テナント管理者に多要素認証を必須にする」、「使い捨てメールドメインリストのURL」、「セキュリティポリシーを保存」がある。](./two-step-verification-mfa-required.png)

必須をやめるには`--mfa-required-for-tenant-admin=false`を指定します。この設定はテナント管理者がログインするときに確認されるので、すでに開いているセッションには適用されず、各テナント管理者の次回のログインから適用されます。設定の効果と対象については、[プラットフォーム全体の既定値とポリシー](../9-platform-policies.md#テナント管理者の2段階認証)を参照してください。

2つ目の認証要素(認証アプリとパスキー)とリカバリーコードをすべて失ったスタッフは、もうログインできません。テナントのほかの管理者も、そのアカウントの2段階認証を解除できません。解除できるのはオペレーターで、[テナントのスタッフ](../3-tenant-staff.md#2段階認証を失った場合)で説明しているとおり`publiractl tenant member reset-mfa`を使います。

認証アプリのシークレットは暗号化キーで暗号化されているので、[古いキーを削除する](./1-rotating-secrets.md#4-古いキーは使われなくなってから削除する)とスタッフがログインできなくなることがあります。パスキーは暗号化されていません。Publiraが保持するのは各パスキーの公開鍵だけで、公開鍵は誰に読まれても何の証明にもならないからです。そのため、キーをローテーションしたり削除したりしても、パスキーはそのまま使えます。

## プラットフォームのオペレーター

オペレーターも同じように、**アカウント設定**の**2段階認証**から、認証アプリと10個のリカバリーコードでプラットフォーム管理画面のアカウントを守れます。[オペレーター自身のアカウント](../1-platform-console.md#オペレーター自身のアカウント)を参照してください。

ロールにかかわらず、すべてのオペレーターに2段階認証を必須にできます。**ポリシー**にある**セキュリティ**で、**Platform Consoleのすべてのオペレーターに2段階認証を必須にする**にチェックを入れて**セキュリティポリシーを保存**を選ぶか、次のコマンドを実行します。

```bash
publiractl policy set --mfa-required-for-platform-operator
```

必須をやめるには`--mfa-required-for-platform-operator=false`を指定します。この設定はオペレーターがログインするときに確認されるので、自分のセッションを含め、すでに開いているセッションには適用されず、各オペレーターの次回のログインから適用されます。2段階認証を設定していないオペレーターに何が表示されるかは、[プラットフォーム全体の既定値とポリシー](../9-platform-policies.md#プラットフォームのオペレーターの2段階認証)を参照してください。必須にしてから自分がログイン時に設定を求められることのないよう、先に自分の認証アプリを設定しておいてください。

認証アプリとリカバリーコードをすべて失ったオペレーターは、もうログインできません。ほかのオペレーターも、プラットフォーム管理画面からそのアカウントの2段階認証を解除することはできません。解除するには、[2段階認証を失ったとき](../1-platform-console.md#2段階認証をなくしたとき)で説明しているとおり`publiractl operator reset-mfa`を使います。このコマンドはアカウントを必要としないので、2段階認証を失ったオペレーターがPubliraで唯一の**スーパー管理者**であっても使えます。

オペレーターの認証アプリのシークレットも、スタッフのものと同じく暗号化キーで暗号化されているので、[古いキーを削除する](./1-rotating-secrets.md#4-古いキーは使われなくなってから削除する)とオペレーターもログインできなくなることがあります。

2段階認証を必須にするかどうかにかかわらず、次の対策をとってください。

- オペレーターごとに本人専用の長いパスワードを設定し、パスワードマネージャーで管理してもらいます。
- **スーパー管理者**のロールはできるだけ少ないオペレーターに限り、閲覧だけが必要な人には**監査担当**を割り当てます。
- アカウントが不要になったオペレーターは、[停止と無効化](../1-platform-console.md#停止と無効化)で説明しているとおり、停止または無効化します。
- VPNやTLS終端でのアドレスの許可リストなどを使い、プラットフォーム管理画面のホスト名を、オペレーターがアクセスするネットワークからだけ使えるようにすることも検討してください。読者やテナントのスタッフがプラットフォーム管理画面を使うことはありません。

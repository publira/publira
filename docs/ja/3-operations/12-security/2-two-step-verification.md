このページでは、オペレーターに向けて、テナントのスタッフとプラットフォーム管理画面のオペレーターが2つ目の認証要素でアカウントを守る仕組みと、それを必須にする方法、認証要素をなくしたときの対処を説明します。

## テナントのスタッフ

テナントのスタッフは、管理画面の**アカウント設定**から、認証アプリと10個のリカバリーコードで自分のアカウントを守れます。スタッフ向けの手順は[自分のアカウント](../../4-console/3-setup/9-your-account.md)で説明しています。

[パスキーでのログイン](../../4-console/3-setup/9-your-account.md#パスキーでのログイン)で説明しているとおり、スタッフはパスキーやセキュリティキーで2段階認証に答えることもできます。後述の必須設定は、認証アプリと同じくパスキーでも満たせます。ログイン時に2段階認証の設定を求められたテナント管理者は、認証アプリの代わりにパスキーを登録してもかまいません。同じアカウントのパスキーと認証アプリは10個のリカバリーコードを共有し、パスキーが拒否された回数は、コードを間違えた回数と合わせてロックの判定に数えられます。

パスキーは、管理画面がどこにあっても管理画面のホストに結び付き、テナントのドメインには結び付きません。管理画面が`admin.<domain>`のようにテナントのドメインの下にある場合も同じです。そのため、管理画面用のドメインを新しく設定したり、管理画面が`admin.<domain>`にあるテナントのドメインを変更したりして[管理画面を別のホストに移す](../2-tenants.md#テナントを別のホスト名に移す)と、スタッフが登録したパスキーはすべて使えなくなります。認証アプリやリカバリーコードを持っているスタッフは、そちらでログインします。2つ目の認証要素がパスキーだけだったスタッフは、必須設定の対象のロールであれば2段階認証の設定をやり直すよう求められ、対象外であればパスワードだけでログインします。管理画面を元のホストに戻すと、古いパスキーはまた使えるようになります。

Publiraのすべてのテナント管理者に2段階認証を必須にできます。プラットフォーム管理画面の**ポリシー**にある**セキュリティ**で、**テナント管理者に多要素認証を必須にする**にチェックを入れて**セキュリティポリシーを保存**を選ぶか、次のコマンドを実行します。

```bash
publiractl policy set --mfa-required-for-tenant-admin
```

![セキュリティポリシーのページの末尾。「テナント管理者に多要素認証を必須にする」、「使い捨てメールドメインリストのURL」、「セキュリティポリシーを保存」があります。](./two-step-verification-mfa-required.png)

必須をやめるには`--mfa-required-for-tenant-admin=false`を指定します。この設定はテナント管理者のログイン時に確認されるので、開いているセッションには影響せず、各テナント管理者が次にログインしたときから適用されます。設定の効果と対象は、[プラットフォーム全体の既定値とポリシー](../9-platform-policies.md#テナント管理者の2段階認証)を参照してください。

2つ目の認証要素(認証アプリとパスキー)とリカバリーコードをすべてなくしたスタッフは、もうログインできません。テナントのほかの管理者も、そのアカウントの2段階認証は解除できません。解除できるのはオペレーターで、[テナントのスタッフ](../3-tenant-staff.md#2段階認証を失った場合)で説明しているとおり`publiractl tenant member reset-mfa`を使います。

認証アプリのシークレットは暗号化キーで暗号化されているので、[古いキーを削除する](./1-rotating-secrets.md#4-古いキーは使われなくなってから削除する)とスタッフがログインできなくなることがあります。パスキーは暗号化していません。Publiraが保存するのは各パスキーの公開鍵だけで、公開鍵は誰に読まれても何の証明にも使えないからです。キーをローテーションしても削除しても、パスキーはそのまま使えます。

## プラットフォームのオペレーター

オペレーターも同じく、**アカウント設定**の**2段階認証**から、認証アプリと10個のリカバリーコードでプラットフォーム管理画面のアカウントを守れます。手順は[オペレーター自身のアカウント](../1-platform-console.md#オペレーター自身のアカウント)を参照してください。

ロールにかかわらず、すべてのオペレーターに2段階認証を必須にできます。**ポリシー**にある**セキュリティ**で、**Platform Consoleのすべてのオペレーターに2段階認証を必須にする**にチェックを入れて**セキュリティポリシーを保存**を選ぶか、次のコマンドを実行します。

```bash
publiractl policy set --mfa-required-for-platform-operator
```

必須をやめるには`--mfa-required-for-platform-operator=false`を指定します。この設定はオペレーターのログイン時に確認されるので、自分のものを含め開いているセッションには影響せず、各オペレーターが次にログインしたときから適用されます。2段階認証を設定していないオペレーターに何が表示されるかは、[プラットフォーム全体の既定値とポリシー](../9-platform-policies.md#プラットフォームのオペレーターの2段階認証)を参照してください。必須にする前に、まず自分の認証アプリを設定しておいてください。そうしないと、自分のログインで設定を求められて初めて、何が必要になるかを知ることになります。

認証アプリとリカバリーコードをすべてなくしたオペレーターは、もうログインできません。ほかのオペレーターも、プラットフォーム管理画面からそのアカウントの2段階認証は解除できません。解除するには、[2段階認証を失ったとき](../1-platform-console.md#2段階認証をなくしたとき)で説明しているとおり`publiractl operator reset-mfa`を使います。このコマンドはアカウントなしで使えるので、2段階認証をなくしたのがPubliraで唯一の**スーパー管理者**であっても解除できます。

オペレーターの認証アプリのシークレットも、スタッフのものと同じく暗号化キーで暗号化されているので、[古いキーを削除する](./1-rotating-secrets.md#4-古いキーは使われなくなってから削除する)とオペレーターもログインできなくなることがあります。

2段階認証を必須にするかどうかにかかわらず、次のことを実施してください。

- オペレーターには、本人専用の長いパスワードをパスワードマネージャーで管理してもらいます。
- **スーパー管理者**のロールはできるだけ少ないオペレーターに限り、閲覧だけが必要な人には**監査担当**を割り当てます。
- アカウントが不要になったオペレーターは、[停止と無効化](../1-platform-console.md#停止と無効化)で説明しているとおり、停止または無効化します。
- プラットフォーム管理画面のホスト名には、VPNやTLS終端でのアドレスの許可リストなどを使い、オペレーターのいるネットワークからしかアクセスできないようにすることも検討してください。読者やテナントのスタッフがプラットフォーム管理画面を使うことはありません。

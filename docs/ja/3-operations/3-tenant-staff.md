テナントのスタッフとは、そのテナントの管理画面にログインする人たちです。このページでは、スタッフが管理画面に入れるようにするまでをオペレーターの側から説明します。最初の管理者の招待、スタッフのロール、管理者が1人も残っていないテナントへの対処を扱います。テナントに管理者ができれば、ほかのスタッフは[メンバー](../4-console/3-setup/6-members.md)で説明するとおり、その管理者がテナント管理画面の**メンバー**で管理します。それ以降オペレーターが関わるのは、何か問題が起きたときだけです。

このページの`publiractl`コマンドは、[プラットフォーム管理画面とpubliractl](./1-platform-console.md#どちらを使うか)と同じ方法で実行します。どのコマンドも、`--tenant`にドメインか公開IDを渡して対象のテナントを指定します。フラグの一覧は[`publiractl`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#tenant)にあります。

## メンバーとユーザー

アカウントはどれも1つのテナントに属します。2つのテナントのサイトで会員登録した読者は、テナントごとに1つずつ、合わせて2つのアカウントを持ちます。アカウントは、属するテナントの**ユーザー**です。ユーザーのうち管理画面のロールも持つ人はテナントのスタッフの**メンバー**で、そのテナントの管理画面にログインできます。

このことから、次のようになります。

- 誰かをスタッフにしても、アカウントが別に作られるわけではありません。ロールを与えられたテナントの読者は、読むときに使っていたメールアドレスとパスワードで管理画面にログインします。
- ロールを外しても、アカウントは残ります。その人はテナントの読者のままで、あとから再びロールを与えることもできます。
- ロールを持っているあいだは、テナントの公開済みのエピソードをサイトでもアプリでも購入せずにすべて読めるので、スタッフは読者と同じ見え方で作品を確認できます。こうしてサイトで有料のエピソードを開くと、価格の横に、ロールによって開けていることと、購入していない読者にはページの代わりに購入の案内が表示されることが示されます。テナントの年齢確認はこの場合も適用されます。また、このアカウントではエピソードを評価できないので、スタッフ自身が読んでもサイトに表示される評価には影響しません。ロールを外すと、この閲覧もできなくなります。

## 3つのロール

| ロール | できること |
| --- | --- |
| **テナント管理者** | 管理画面のすべての操作ができます。スタッフとその招待、テナントのすべての設定、サイトとブランディング、メールや決済、プッシュ通知、ログイン、Googleタグとの連携、読者のアカウントとお問い合わせ、アクセスチケット、購入と返金、印税、監査ログを扱えます |
| **編集担当** | シリーズ、エピソード、著者、レーベル、ジャンルといった作品の情報と、テナントのページ、お知らせ、キャンペーンバナーを作成、編集できます。コメントの管理もできます |
| **監査担当** | 編集担当が扱うものとテナントの設定を閲覧できます。変更はできません |

表で上にあるロールは、それより下のロールができることをすべてできます。管理画面には、そのロールで使えないものは表示されません。編集担当のサイドバーには**メンバー**、**読者**、**印税**、**購入**が表示されず、監査担当には変更を行うボタンが一切表示されません。

ほかの人にロールを与えられるのはテナント管理者だけなので、テナントには少なくとも1人のテナント管理者が必要です。

## スタッフにアクセス権を与える

方法は3つあります。どれが合うかは、相手がすでにテナントにアカウントを持っているかどうかと、インストールがメールを送るかどうかで決まります。

### テナント管理者を招待する

招待はメールアドレスあてに送られ、承諾されるとそのアドレスがテナント管理者になります。新しいテナントの最初の管理者は、たいていテナントの作成時に指定したアドレスへの招待で決まります。あとから管理者を増やすときも、この方法を使います。

- プラットフォーム管理画面では、**テナント一覧**からテナントを開いて**メンバー管理**を選び、**テナント管理者を招待**にメールアドレスを入力して**管理者を招待**を選びます。
- `publiractl`では、`publiractl tenant invite create --tenant comics.example.com --email editor-in-chief@comics.example.com`を実行します。

![プラットフォーム管理画面のテナントのメンバー管理画面。基本情報タブとメンバー管理タブがあり、テナント管理者を招待の欄に、招待するメールアドレスの入力欄と管理者を招待ボタンがある。](./tenant-staff-invite-admin.png)

招待された人には、テナントの管理画面へのリンクが、テナントの既定言語のメールで届きます。リンク先で**お名前**と**パスワード**を入力し、**招待を承諾する**を選んでログインします。リンクの有効期限は24時間です。

招待したアドレスがすでにテナントのユーザーのものなら、招待は作られません。そのアドレスはその場でテナント管理者になり、メールも送られません。それまでのロールは置き換わるので、編集担当をこの方法で招待するとテナント管理者になります。

招待メールは`publira worker`が送ります。テナントが独自のSMTP設定を保存していればそれを使い、なければプラットフォームのSMTP設定を使います。ワーカーが動いていないインストールでは、招待は作成されますが、メールは送られません。

プラットフォーム管理画面や`publiractl`から送る招待では、テナント管理者にすることしかできません。編集担当や監査担当にするには、[既存のユーザーを追加する](#既存のユーザーを追加する)の方法でロールを与えるか、テナントの管理者に招待してもらいます。テナント管理画面からの招待では、3つのロールのどれでも与えられます。

### 送った招待を確認する

同じ**メンバー管理**画面の**招待一覧**には、テナントの招待がすべて表示されます。テナントの管理者がテナント管理画面から送った招待もここに含まれます。招待ごとに、承諾したときに与えられる**ロール**と、**招待中**、**承諾済み**、**取り消し**、**期限切れ**のいずれかの状態が表示されます。

- 招待中か期限切れの招待で**再送**を選ぶと、新しいリンクで招待がもう一度送られ、そこから24時間有効になります。以前のリンクは使えなくなります。
- 招待中の招待で**取り消し**を選ぶと、招待は取り下げられ、リンクも使えなくなります。

![招待一覧。期限切れになった編集担当への招待、取り消したテナント管理者への招待、期限切れになったテナント管理者への招待が並び、それぞれにロール、作成日時、有効期限、再送ボタン、取り消しボタンがある。](./tenant-staff-invitations.png)

コマンドラインでは、`publiractl tenant invite list --tenant comics.example.com`で各招待をIDとともに表示し、`tenant invite resend --id <ID>`や`tenant invite cancel --id <ID>`で1件ずつ操作します。期限切れの招待も操作できます。

テナントの管理者も、テナント管理画面で同じ招待を確認でき、招待を送ったり、再送したり、取り消したりできます。

### 既存のユーザーを追加する

テナントの読者には、メールを使わずに3つのロールのどれでも直接与えられます。

- プラットフォーム管理画面では、テナントの**メンバー管理**画面で**メンバーを追加**にメールアドレスを入力し、**ロール**を選んで**メンバーを追加**を選びます。
- `publiractl`では、`publiractl tenant member add --tenant comics.example.com --email reader@example.com --role tenant_editor`を実行します。`--role`には`tenant_admin`、`tenant_editor`、`tenant_auditor`のいずれかを指定します。

![メンバーを追加の欄。追加するユーザーのメールアドレス、ロール、メンバーを追加ボタンがある。](./tenant-staff-add-member.png)

この方法を使えるのは、テナントにアカウントがすでにあるメールアドレスだけで、それ以外のアドレスは受け付けられません。アカウントのない人には、先にテナントのサイトで会員登録してもらうか、テナント管理者として招待します。すでにロールを持つアカウントは、代わりに**ロール変更**でロールを変えます。

### メールを使わずにアカウントを作成する

`publiractl tenant admin create`は、管理画面のアカウントをその場で作成します。アカウントにはパスワードが設定され、メールアドレスは確認済みとして扱われるので、すぐにログインできます。メールは一切送らないので、メールを送らないインストールでは、最初の管理者もその後のスタッフもこの方法で用意します。

```bash
publiractl tenant admin create \
  --tenant comics.example.com \
  --email owner@comics.example.com \
  --name Owner \
  --generate-password
```

`--generate-password`を指定すると、パスワードはターミナルに一度だけ表示され、ほかのどこにも残りません。ターミナルを閉じる前に本人に伝えてください。パスワードのほかの設定方法は[リファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#tenant)にあります。`--role`を指定すると、テナント管理者ではなく編集担当か監査担当を作成します。プラットフォーム管理画面には、同じことをする機能はありません。

指定するメールアドレスは、まだテナントにアカウントがないものに限ります。アカウントがすでにあるアドレスには、代わりに`tenant member add`を使います。

## ロールの変更とメンバーの削除

プラットフォーム管理画面のテナントの**メンバー管理**画面では、**ロール変更**でメンバーに別のロールを与え、**削除**でメンバーからすべてのロールを外します。

![メンバーの一覧。テナント管理者、編集担当、監査担当が並び、それぞれにメールアドレス、ロール、状態、参加日時、ロール変更ボタン、削除ボタンがある。](./tenant-staff-members.png)

コマンドラインでは、次のように操作します。

```bash
publiractl tenant member list --tenant comics.example.com
publiractl tenant member update-role --tenant comics.example.com --user <public ID> --role tenant_auditor
publiractl tenant member remove --tenant comics.example.com --user <public ID>
```

`--user`に渡す公開IDは、`tenant member list`で確認できます。

管理画面はリクエストのたびにメンバーのロールを確認するので、変更はすぐに、メンバーがすでに開いている管理画面にも反映されます。削除されたメンバーにもテナントの読者としてのアカウントは残るので、購入や履歴は引き続き本人のものです。

## 2段階認証を失った場合

2段階認証を有効にしていたスタッフが、認証アプリやパスキーといった2つ目の要素をすべて失い、リカバリーコードもすべて失うと、管理画面にログインできなくなります。テナントのスタッフには、そのアカウントの2段階認証を解除できる人はいません。オペレーターなら、次のコマンドで解除できます。

```bash
publiractl tenant member reset-mfa --tenant comics.example.com --email editor@comics.example.com
```

`--email`の代わりに`--user <public ID>`でアカウントを指定することもできます。このコマンドが削除するのは、アカウントの認証アプリと、どの管理画面のアドレスで登録したかを問わず登録済みのすべてのパスキー、すべてのリカバリーコードだけです。パスワードとロールはそのまま残ります。メンバーはパスワードだけでログインし、[自分のアカウント](../4-console/3-setup/9-your-account.md)で説明するとおり、**アカウント設定**から2段階認証を設定し直します。プラットフォームがそのロールに2段階認証を必須にしている場合は、ログインするときに管理画面が設定を求めます。

解除したアカウントはパスワードだけで守られることになり、それはパスワードを盗んだ人が求めてくる状態そのものです。コマンドを実行する前に、依頼がそのメンバー本人から来たものか確認してください。確認には、依頼が届いた経路ではなく、本人のものだとすでにわかっている連絡手段を使います。

解除の操作は、実行者を**コマンドライン**として、プラットフォーム管理画面の**監査ログ**に記録されます。プラットフォーム管理画面自体には、同じことをする機能はありません。

## 管理者がいなくなったテナントを復旧する

テナント管理画面では最後のテナント管理者を降格することも削除することもできないので、ふつうテナントには必ず管理者がいます。それでも実際には、管理者が出版社を辞めたり、メールボックスに入れなくなったり、アカウントを乗っ取られたりして、最後の管理者を失うことがあります。

オペレーターが手を打てるように、プラットフォーム管理画面と`publiractl`は、最後のテナント管理者を残すようには制限していません。状況ごとの対処は次のとおりです。

| 状況 | 対処 |
| --- | --- |
| スタッフの誰かが引き継ぐ | **ロール変更**か`tenant member update-role --role tenant_admin`で、その人のアカウントにテナント管理者のロールを与えます |
| 新しい管理者がテナントにアカウントを持っていない | その人を招待します。メールを受け取れないときは、`publiractl tenant admin create`でアカウントを作成します |
| 最後の管理者が2段階認証を失った | [2段階認証を失った場合](#2段階認証を失った場合)で説明するとおり`tenant member reset-mfa`で解除すれば、その人はパスワードで再びログインできます |
| 最後の管理者のアカウントが乗っ取られた | 先に別の人にロールを与え、それから乗っ取られたアカウントを**削除**でメンバーから外します。外したアカウントは、その時点で管理画面に入れなくなります。ただし読者としてテナントのサイトには引き続きログインできるので、新しい管理者がテナント管理画面の**読者**から停止します |

こうした変更はどれも、プラットフォーム管理画面の**監査ログ**に、変更したオペレーターとともに記録されます。`publiractl`から行った変更の実行者は**コマンドライン**です。テナントのスタッフがテナント管理画面で行った変更は、プラットフォーム管理画面ではなくテナントの監査ログに記録されます。

テナントのスタッフとは、そのテナントの管理画面にログインする人のことです。このページでは、スタッフが管理画面を使えるようになるまでをオペレーターの立場から説明します。扱うのは、最初の管理者の招待、スタッフのロール、管理者が1人もいなくなったテナントへの対処です。テナントに管理者ができたら、ほかのスタッフはその管理者がテナント管理画面の**メンバー**で管理します。詳しくは[メンバー](../4-console/3-setup/6-members.md)を参照してください。その後オペレーターの出番は、何か問題が起きたときだけです。

このページの`publiractl`コマンドは、[プラットフォーム管理画面とpubliractl](./1-platform-console.md#どちらを使うか)の説明どおりに実行します。どのコマンドでも、対象のテナントは`--tenant`にドメインか公開IDを渡して指定します。すべてのフラグは[`publiractl`のリファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#tenant)に載っています。

## メンバーとユーザー

アカウントはどれも1つのテナントに属します。2つのテナントのサイトで会員登録した読者は、テナントごとに1つずつ、合わせて2つのアカウントを持ちます。アカウントは、それが属するテナントの**ユーザー**です。ユーザーのうち管理画面のロールも持つ人はテナントのスタッフの**メンバー**で、そのテナントの管理画面にログインできます。

ここから次のことが言えます。

- 誰かをスタッフにしても、その人のアカウントは移りません。テナントの読者にロールを与えると、その人は読者として使っていたメールアドレスとパスワードのまま管理画面にログインします。
- ロールを外しても、その人のアカウントは残ります。その人はテナントの読者のままで、あとからまたロールを与えることもできます。
- ロールを持っている間は、テナントの公開済みのエピソードを、サイトでもアプリでも購入せずにすべて読めます。スタッフは読者が見るとおりに作品を確認できます。サイトで有料のエピソードをこうして開くと、価格の横に2つのことが表示されます。ロールがあるので開けていることと、購入していない読者にはページの代わりに購入の案内が表示されることです。テナントの年齢確認はこの場合も適用されます。また、ロールで読んでいるアカウントはエピソードを評価できないので、スタッフ自身の閲覧はサイトに表示される評価に影響しません。ロールを外すと、こうした閲覧もできなくなります。

## 3つのロール

| ロール | できること |
| --- | --- |
| **テナント管理者** | 管理画面のすべての操作。スタッフとその招待、テナントのすべての設定、サイトとブランディング、メールや決済、プッシュ通知、ログイン、Googleタグとの連携、読者のアカウントとお問い合わせ、アクセスチケット、購入と返金、印税、監査ログを扱えます |
| **編集担当** | シリーズ、エピソード、著者、レーベル、ジャンルといった作品の情報と、テナントのページ、お知らせ、キャンペーンバナーを作成、編集できます。コメントの管理もできます |
| **監査担当** | 編集担当が扱うものとテナントの設定を閲覧できます。変更はできません |

表で上にあるロールは、その下にあるロールができることをすべてできます。管理画面には、そのロールで使えないものは表示されません。編集担当のサイドバーには**メンバー**、**読者**、**印税**、**購入**が表示されず、監査担当には変更を行うボタンが一切表示されません。

ほかの人にロールを与えられるのはテナント管理者だけです。そのため、テナントには少なくとも1人のテナント管理者が必要です。

## スタッフにアクセス権を与える

方法は3つあります。どれを使うかは、相手がすでにテナントにアカウントを持っているかどうかと、運用中のPubliraがメールを送るかどうかで決まります。

### テナント管理者を招待する

招待はメールアドレスあてに送られ、相手が承諾するとそのアドレスのアカウントがテナント管理者になります。新しいテナントの最初の管理者は、ふつうはテナントの作成時に指定したアドレスへの招待で決まります。あとから管理者を増やすときもこの方法を使います。

- **プラットフォーム管理画面**の場合は、**テナント一覧**からテナントを開いて**メンバー管理**を選びます。**テナント管理者を招待**にメールアドレスを入力し、**管理者を招待**を選びます。
- **publiractl**の場合は、`publiractl tenant invite create --tenant comics.example.com --email editor-in-chief@comics.example.com`を実行します。

![プラットフォーム管理画面にあるテナントのメンバー管理画面。基本情報タブとメンバー管理タブがあり、テナント管理者を招待の欄に招待するメールアドレスの入力欄と管理者を招待ボタンがある。](./tenant-staff-invite-admin.png)

招待された人には、テナントの管理画面へのリンクがテナントの既定言語のメールで届きます。リンクを開いて**お名前**と**パスワード**を入力し、**招待を承諾する**を選ぶとログインできます。リンクの有効期限は24時間です。

招待したアドレスがすでにテナントのユーザーのものであれば、招待は作られません。そのアドレスのアカウントはその場でテナント管理者になり、メールも送られません。それまでのロールは置き換えられるので、編集担当をこの方法で招待するとテナント管理者になります。

招待メールは`publira worker`が送ります。テナントが独自のSMTP設定を保存していればそれを使い、なければプラットフォームのSMTP設定を使います。ワーカーが動いていない場合、招待は作成されますがメールは送られません。

プラットフォーム管理画面や`publiractl`から送る招待では、テナント管理者しか作れません。編集担当や監査担当にするには、[既存のユーザーを追加する](#既存のユーザーを追加する)の方法でロールを与えるか、テナントの管理者に招待してもらいます。テナント管理画面からの招待なら、3つのロールのどれでも与えられます。

### 送った招待を確認する

同じ**メンバー管理**画面の**招待一覧**には、テナントの招待がすべて表示されます。テナントの管理者がテナント管理画面から送った招待も含みます。招待ごとに、承諾したときに与えられる**ロール**と、**招待中**、**承諾済み**、**取り消し**、**期限切れ**のいずれかの状態が表示されます。

- 招待中か期限切れの招待で**再送**を選ぶと、新しいリンクで招待がもう一度送られ、そこから24時間有効になります。以前のリンクは使えなくなります。
- 招待中の招待で**取り消し**を選ぶと招待が取り下げられ、そのリンクは使えなくなります。

![招待一覧。期限切れになった編集担当への招待、取り消したテナント管理者への招待、期限切れになったテナント管理者への招待が、それぞれロール、作成日時、有効期限、再送ボタン、取り消しボタンとともに並んでいる。](./tenant-staff-invitations.png)

コマンドラインでは、`publiractl tenant invite list --tenant comics.example.com`で招待の一覧をIDとともに表示できます。個々の招待は`tenant invite resend --id <ID>`と`tenant invite cancel --id <ID>`で操作します。期限切れの招待にも使えます。

テナントの管理者も、テナント管理画面で同じ招待を確認し、招待の送信、再送、取り消しができます。

### 既存のユーザーを追加する

テナントの読者には、メールを使わずに3つのロールのどれでも直接与えられます。

- **プラットフォーム管理画面**の場合は、テナントの**メンバー管理**画面で**メンバーを追加**にメールアドレスを入力し、**ロール**を選んで**メンバーを追加**を選びます。
- **publiractl**の場合は、`publiractl tenant member add --tenant comics.example.com --email reader@example.com --role tenant_editor`を実行します。`--role`には`tenant_admin`、`tenant_editor`、`tenant_auditor`のいずれかを指定します。

![メンバーを追加の欄。追加するユーザーのメールアドレス、ロール、メンバーを追加ボタンがある。](./tenant-staff-add-member.png)

この方法を使えるのは、テナントにアカウントがすでにあるメールアドレスだけです。それ以外のアドレスは受け付けられません。アカウントのない人には、先にテナントのサイトで会員登録してもらうか、テナント管理者として招待します。すでにロールを持っているアカウントのロールは、**ロール変更**で変えます。

### メールを使わずにアカウントを作成する

`publiractl tenant admin create`を使うと、管理画面のアカウントをその場で作成できます。アカウントにはパスワードが設定され、メールアドレスは確認済みとして扱われるので、すぐにログインできます。メールは送られません。メールを送らない構成では、最初の管理者もその後のスタッフもこの方法で用意します。

```bash
publiractl tenant admin create \
  --tenant comics.example.com \
  --email owner@comics.example.com \
  --name Owner \
  --generate-password
```

`--generate-password`を指定すると、パスワードはターミナルに一度だけ表示され、ほかには残りません。ターミナルを閉じる前に本人に伝えてください。パスワードのほかの設定方法は[リファレンス](https://github.com/publira/publira/blob/main/server/cmd/publiractl/README.md#tenant)に載っています。`--role`を指定すると、テナント管理者ではなく編集担当か監査担当のアカウントを作成します。プラットフォーム管理画面には、この操作に当たる機能はありません。

指定するメールアドレスには、テナントのアカウントがまだあってはいけません。アカウントがすでにあるアドレスには、代わりに`tenant member add`を使います。

## ロールの変更とメンバーの削除

プラットフォーム管理画面のテナントの**メンバー管理**画面では、**ロール変更**でメンバーのロールを変え、**削除**でメンバーのロールをすべて外します。

![メンバーの一覧。テナント管理者、編集担当、監査担当が、それぞれメールアドレス、ロール、状態、参加日時、ロール変更ボタン、削除ボタンとともに並んでいる。](./tenant-staff-members.png)

コマンドラインでは次のように操作します。

```bash
publiractl tenant member list --tenant comics.example.com
publiractl tenant member update-role --tenant comics.example.com --user <public ID> --role tenant_auditor
publiractl tenant member remove --tenant comics.example.com --user <public ID>
```

`--user`に渡す公開IDは、`tenant member list`で各メンバーの分を確認できます。

管理画面はリクエストのたびにメンバーのロールを確認するので、変更はすぐに反映されます。メンバーがすでに開いている管理画面にも反映されます。削除されたメンバーもテナントの読者としてのアカウントは残るので、購入や履歴はそのまま本人のものです。

## 2段階認証を失った場合

2段階認証を有効にしたスタッフが、認証アプリやパスキーといった2つ目の要素をすべて失い、リカバリーコードもすべて失うと、管理画面にログインできなくなります。テナントのスタッフには、その人のアカウントから2段階認証を解除できる人がいません。オペレーターは次のコマンドで解除できます。

```bash
publiractl tenant member reset-mfa --tenant comics.example.com --email editor@comics.example.com
```

アカウントは`--email`の代わりに`--user <public ID>`で指定することもできます。このコマンドが削除するのは、アカウントの認証アプリ、登録済みのすべてのパスキー、すべてのリカバリーコードだけです。パスキーは、どの管理画面のアドレスで登録したものであってもすべて削除されます。パスワードとロールは変わりません。メンバーはその後パスワードだけでログインし、[自分のアカウント](../4-console/3-setup/9-your-account.md)の説明どおりに**アカウント設定**から2段階認証を設定し直します。プラットフォームがそのロールに2段階認証を必須にしていれば、ログインしたときに管理画面が設定を求めます。

2段階認証を解除すると、アカウントを守るのはパスワードだけになります。これは、盗んだパスワードを持つ人がまさに求めることです。コマンドを実行する前に、依頼が本当にそのメンバーからのものかを確かめてください。確かめるときは、依頼が届いた経路ではなく、本人のものだとすでにわかっている連絡先を使います。

解除はプラットフォーム管理画面の**監査ログ**に、実行者を**コマンドライン**として記録されます。プラットフォーム管理画面自体には、この操作に当たる機能はありません。

## 管理者がいなくなったテナントを復旧する

テナント管理画面では最後のテナント管理者を降格することも削除することもできないので、ふつうテナントには必ず管理者がいます。それでも、管理者が出版社を辞めた、メールボックスにアクセスできなくなった、アカウントを乗っ取られたといった事情で、最後の管理者がいなくなることは実際にあります。

オペレーターが対処できるように、プラットフォーム管理画面と`publiractl`には、最後のテナント管理者を残すための制限がありません。

- **スタッフの誰かが引き継ぐ場合**は、その人のアカウントに**ロール変更**か`tenant member update-role --role tenant_admin`でテナント管理者のロールを与えます。
- **新しい管理者がテナントにアカウントを持っていない場合**は、その人を招待します。メールを受け取れない場合は`publiractl tenant admin create`でアカウントを作成します。
- **最後の管理者が2段階認証を失った場合**は、[2段階認証を失った場合](#2段階認証を失った場合)の説明どおり`tenant member reset-mfa`で解除します。その人はパスワードでまたログインできるようになります。
- **最後の管理者のアカウントが乗っ取られた場合**は、まず別の人にテナント管理者のロールを与えます。そのあと乗っ取られたアカウントを**削除**でメンバーから外すと、そのアカウントはすぐに管理画面に入れなくなります。ただし、読者としてテナントのサイトにはまだログインできます。新しい管理者は、テナント管理画面の**読者**からこのアカウントを停止できます。

こうした変更はどれも、プラットフォーム管理画面の**監査ログ**に記録されます。実行者として、変更したオペレーターか、`publiractl`からの変更であれば**コマンドライン**が記録されます。テナントのスタッフがテナント管理画面で行った変更は、プラットフォーム管理画面ではなくテナントの監査ログに記録されます。

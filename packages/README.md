# packages

The packages shared across the Node.js side of the repository.

## Package list

- `api-client/`: the ConnectRPC TypeScript client for the APIs (regenerated by `task gen`)
- `brand/`: the brand tokens for the web apps (`theme.css`)
- `email-templates/`: the shared React Email layout and templates (`email-renderer` turns them into HTML and text)
- `i18n/`: the message catalog loader that reads the root `locales/`, and the generated message types (the `./catalog` / `./messages` subpaths)
- `icons/`: the shared icon components wrapping `lucide-react`
- `layouts/`: the layout components shared by several web apps
- `next-cache-handlers/`: the Redis-backed Next.js `cacheHandler` / `cacheHandlers` (for self-hosted multi-instance deploys)
- `tracing/`: the OpenTelemetry registration shared by the Next.js apps (called from `instrumentation.ts`)
- `tsconfig/`: the TypeScript configuration shared across the workspace
- `ui-components/`: the UI components shared by `web-host` and `web-admin`
- `utils/`: the shared utilities (`cn` and friends)
- `web-session/`: the jose JWE session cookie helpers for Next.js, including attaching the Bearer token

## Working rules

- Everything under `api-client/src/gen/` is generated; never edit it by hand
- An API change starts in `proto/`, then `task gen` regenerates the client
- When a `brand/` token changes, check what it affects in the UI
- `layouts/` and `ui-components/` put staying consistent with Base UI and the brand tokens first
- A change to `tsconfig/` reaches every app, so check the impact across them
- `ui-components/` favors reusable parts that assume a per-tenant theme
- `utils/` holds only general-purpose code with no dependency on a specific app
